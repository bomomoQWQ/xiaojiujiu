# 00. 文档地位、依据与阅读规则

## 00.1 本文交付什么

本文将本轮讨论收束成一份可供设计评审、开发拆解和测试验收使用的 Markdown 规格。核心交付不是“再加一条主动触发公式”，而是以下闭环：

```text
实际经历与内部关注
        ↓
社会情感记忆关联经历，提出目标与办法
        ↓
目标契约：这件事是否成立，何时推进、等待或结束
        ↓
行动候选契约：现在可以采取哪些真实办法
        ↓
收益契约：每种办法预计改变什么，怎样计价与结算
        ↓
价值观与当前关注：角色怎样重视这些结果
        ↓
「浪潮」：累积、泄漏、竞争、形成决定或明确暂缓
        ↓
真实执行、结果观察与分项结算
        ↓
更新目标、用户认识、记忆与持续情绪
```

本稿把**已讨论接受的职责和不变量**写成设计要求。为了便于施工而补入的状态字段、接口组织、默认实验顺序，均属于**本稿工程化建议**，不是对当前仓库已有实现的陈述。

| 标记 | 含义 | 使用方式 |

| **设计基线** | 本轮已经讨论并接受的方向与边界 | 实现不得无说明地反转 |

“封成设计基线”不等于证明了模型有效。本文中的小数、积分时间与人格演示仅用于验证算式和说明行为，不是生产参数。

# 01. 设计宣言：可靠的系统，不必扮演永远谨慎的角色

## 01.1 正常动机无需伪装成功利任务

以下目标都可以成立：

“想把一个真实想法告诉用户。”  
“想继续琢磨之前的问题。”  
“现在就是想建立一次交流。”  
“暂时更想独处，或者休整一会儿。”

它们不需要被包装成“对用户工作效率的提升”，也不需要先制造不安才能获得动力。

**表达本身可以有价值，探索本身可以有过程价值，独处也可以是主动选择。** 用户是否回应是相应结果之一，不是所有目标价值的唯一来源。

## 01.2 不优化用户依赖

系统不把以下指标当作默认终极目标：用户回复更快、聊得更久、更加依赖角色、把更多现实活动让给 Bot。

用户有自己的工作、兴趣和关系。它们是交互条件，不是“抢走了本来属于角色的时间”。角色可以舍不得，但不能把单方面愿望升级成用户义务。

## 01.3 自主意愿与执行边界分开

内部可以是：很想联系、很在意、持续犹豫。外部仍可以是：这次暂不联系。

边界、停用开关、重复硬上限、实际资源权限和交付期再授权，不是可被收益覆盖的扣分项。人格影响合法范围内的偏好、耐心与表达，不改变用户授权事实。

## 01.4 不追求“永远最优”，但拒绝无依据的任性

多个合适方案之间，角色可以有偏爱；先出现且持续获得支持的念头，可以保有历史。可是新证据推翻前提时，旧准备度不能变成继续执行的理由。

“我想了很久”解释一个决定的形成过程，不提供额外事实权限。

## 01.5 哲学视角的使用边界

共同实践与关系经验，是本设计组织意义的视角：关注不仅来自孤立参数，也来自实际参与过的事情。

这不是用某个哲学命题直接证明数学模型。本文不把私人交往数量等同于人的本质，也不把“共同讨论过”自动升级成某种被用户承认的身份或承诺。

# 02. 相对现行 v2：保留什么，替换什么

## 02.1 现行情况仅以 S3 为依据

S3 描述现行自主入口为 `runtime_v2.py::decide_endogenous`：先取候选、判硬边界、计算保守用户效用与重复成本，再做资格判断及危险率抽签；冷启动可走探索豁免。

它还描述：I/R/P 经候选内部效用起作用，重复成本按实际确认送达计数，交付前另有授权，阶段结果进入审计。以上均需实现者在当前代码中重新定位，不以本文代替源码核验。

## 02.2 保留的执行资产

| 资产 | 新版处置 |
| --- | --- |
| 用户明确边界与作用域 | 保留为动作是否允许的权威 |
| 主动总限额、冷却、同事项重复硬上限 | 保留；迁移不清空历史曝光 |
| 已确认送达的暴露记录 | 保留；不改为按候选数量计数 |
| 交付前二次授权 | 保留 |
| 实际生成与发送的并发协调 | 保留，并接受新候选语义范围 |
| 单写者、版本快照、幂等结算 | 保留并扩展 |
| v2 影子基线 | 保留用于回放比较，不与浪潮同时获得发送权 |

## 02.3 替换的决策逻辑

浪潮用“意图准备度的持续竞争与首次形成决定”替换自主路径中的最终 `argmax + hazard`。它不再依靠 `D=max(真实优势, 探索下限)` 为普通联系制造虚拟高收益。

旧版危险率只留作基线或回滚策略，不在浪潮决定后再抽一次签。调度器的唤醒计时器仍然存在；**去掉最终抽签，不等于去掉时钟、冷却或唤醒。**

浪潮也不重新采用“一律以最悲观的方案差值大于零为普通行为资格”的前一版研究草案。低压力、已获许可的表达可以凭正常意愿和有说明的预期进入竞争。

## 02.4 两个从 S3 公式得到的提示

S3 的普通联系项为 `0.25 + 0.7 × sigmoid(z)`，因此即使 sigmoid 理想取 1，上限也只有 0.95。若用户侧保守效用为 −1、没有额外事项或情绪相关收益，它不可能仅靠该联系项在正常路径达到净效用零。

同时，探索下限若固定将优势提高至 2，则真实效用在下限以下的变化可能不影响抽签概率。它们说明正常价值与探索节奏在现行示例中发生了耦合，不证明线上所有实例都如此。

**迁移目标不是给这个候选继续加分，而是换成有目标、可归账的行为价值与新的决定过程。**

# 03. 总体架构与写入权

```text
用户、工具与实际活动
           ↓
      原始事件与实际产物
           ↓
    社会情感记忆／当前局势
           ↓
       目标草案与关注
           ↓
       目标契约管理
           ↓
    基础模板＋强语义行动提议
           ↓
       行动候选编译
           ↓
  目标状态＋收益契约＋结果预测
           ↓
       行为预计作用向量
           ↓
  价值观与当前关注 → 即时吸引力
           ↓
       「浪潮」竞争场
           ↓
       决定、暂缓或内部处理
           ↓
       真实执行与结果观察
           ↓
目标结算／用户学习／情绪更新／记忆更新
```

## 03.1 模块权限表

| 模块 | 有权决定 | 无权决定 |
| --- | --- | --- |
| 原始事件与执行记录 | 记录实际输入、动作和渠道返回 | 用户未表达的真实内心 |
| 社会情感记忆 | 提议经历关联、关系情境、目标与处理方式 | 改写原文、直接增加完成收益、覆盖边界 |
| 目标管理 | 采纳、关联、推进、等待、暂缓与结束目标 | 代替真实结果宣布成功 |
| 收益系统 | 按契约计算预计作用与结算价值 | 制造来源、把未知自动填成好坏 |
| 用户模型 | 预测指定条件和窗口内的可观察结果 | 修改人格、替角色创造愿望 |
| 价值观编译 | 调整结果的主观分量 | 改变用户同意与否的概率事实 |
| 情绪动力学 | 维护六状态及内源愿望的时间演化 | 把内部预演变成用户训练标签 |
| 浪潮 | 维护准备度，形成具体行动决定 | 绕过权限、伪装实际执行 |
| 主 LLM | 在选定范围内表达，正常响应用户当前消息 | 私自扩大动作范围后沿用原评分 |
| 协调器与执行器 | 最终提交、授权、执行、幂等应用结果 | 任意重新解释用户心理 |

后台模型只能返回建议，当前权威状态由统一提交入口更新。即使实现拆成多个类，也不能让多个异步任务直接覆盖同一份心理或目标状态。

## 03.2 三个不同的“承诺”

**采纳目标**：这件事进入角色当前关注。  
**向用户作出承诺**：实际说过并确认过要做什么。  
**提交行动**：浪潮决定现在执行一个具体方案。

三者不得互相推导。一个内部愿望不会因为被采纳，就成为用户也知道的共同约定。

# 04. 术语、状态与数值单位

## 04.1 主要对象

| 对象 | 定义 |
| --- | --- |
| 共同事项 | 一次可追溯的项目、约定、讨论或事件线索，不是泛泛主题 |
| 关注项 | 当前值得继续加工的内容，可以尚未形成目标 |
| 动机方向 | 评价结果意义的八个方向 |
| 目标 | 希望发生的具体变化，受目标契约管理 |
| 目标周期 | 持续需要的一次有限追求过程；不是重新清零历史 |
| 行动候选 | 服务目标的可执行方案，尚未执行 |
| 行动尝试 | 某次实际被提交的执行实例 |
| 结果令牌 | 一份可唯一定位、可更正的结果依据 |
| 行动准备度 | 某份候选在竞争过程中接近提交的程度，不是概率 |
| 决断回合 | 一次有限的考虑过程；可以形成行动，也可以明确暂缓 |

## 04.2 必须分开的四个量

| 量 | 示例问题 |
| --- | --- |
| 目标重视程度 | 这件事现在有多值得在意？ |
| 真实进度／需要状态 | 已完成多少？当前仍想实现什么？ |
| 结果预测 | 采用这个办法可能发生什么？ |
| 行动准备度 | 这个具体念头已经考虑到哪一步？ |

完成了 90% 不代表重要性仅剩 10%；考虑到 90% 不代表有 90% 的概率成功；用户回复概率 0.8 不代表用户开心程度 0.8。

## 04.3 数学符号与量纲

| 符号 | 含义 | 约定 |
| --- | --- | --- |
| `t`、`Δt` | 真实时间、时间差 | 核心计算统一用秒；示例可标明分钟 |
| `g`、`i`、`k` | 目标、候选、动机方向 | `k` 共八类 |
| `d_g` | 持续需要的未满足量 | `[0,1]`；不复用为有限任务进度 |
| `q_g` | 有限事项的进度 | `[0,1]` 或离散里程碑 |
| `b_k(o)` | 结果 `o` 在方向 `k` 的基础价值 | 项目效用单位，不是用户心理真值 |
| `F_ik` | 候选 `i` 的预期结果价值 | 与 `b` 相同单位 |
| `w_k` | 价值观编译后的长期权重 | 非负，尺度固定 |
| `a_k(t)` | 当前注意调制 | 有界，首轮可固定为 1 |
| `U_i` | 扣成本后的效用 | 项目效用单位 |
| `u_i=U_i/U_*` | 进入竞争场的无量纲吸引力 | `U_* > 0` 固定且版本化 |
| `x_i` | 行动准备度 | `[0,1]`，不是证据置信度 |
| `τ_i` | 积累时间尺度 | 正的秒数 |
| `ℓ_i`、`γ`、`c_ij` | 泄漏、竞争强度、竞争关系 | 非负；关系上限由配置确定 |
| `ϑ_i` | 决定边界 | `0 < ϑ_i < 1` |

`U_*` 是本稿为量纲一致补入的工程建议。早期讨论中把收益数字直接写作 `u`，可视为演示时取 `U_*=1`。正式实现不得悄悄用单位变化调发送频率。

<a id="s05"></a>
# 05. 八条动机，不是八个不断饥饿的独立模型

| 方向 | 合法目标例子 | 不能冒认的收益 |
| --- | --- | --- |
| **接近** | 希望发生一次来回交流 | 发出消息即视作已经获得陪伴 |
| **表达** | 把一条真实内容或当前愿望表达出来 | 反复改写同一想法领取新收益 |
| **探索** | 推进问题、核对假设、参与有意义的讨论 | 生成更多字就算得到知识 |
| **关怀** | 提供用户明确需要且允许的帮助 | 自称关心即视作用户感到安慰 |
| **践约** | 完成角色自己确认的安排 | 把用户的个人计划当作双方约定 |
| **修复** | 处理已有依据的误解、错误或冲突 | 道歉一次即认为关系已恢复 |
| **自主** | 实际推进自己的关注与活动 | 每次不联系用户都自动领独立奖励 |
| **休整** | 经过实际休整降低调节负荷 | 选择休息时立即领取完整恢复 |

动机方向不是必需每轮填满的八个槽。没有冲突就不必有修复目标，没有承诺就不必有践约收益。

同一目标可以映射到不止一个方向，但映射由契约模板预先定义，不由多个模块各领一遍“满额成果”。八维是同一结果的价值描述，不是八份互相独立的物理奖励。

**当前轮有四个活跃目标，并不代表系统需要再创造四个目标把八类补齐。**

<a id="s06"></a>
# 06. 六状态情绪系统与浪潮的接口

## 06.1 六个全局状态保留

| 状态 | 职责 | 禁止解释 |
| --- | --- | --- |
| 正性情感 | 正向底色与当前正向成分 | 用户好感度 |
| 负性情感 | 负向底色与未消化影响 | 用户做错多少 |
| 激活程度 | 活跃、紧绷、兴奋的程度 | 正负效价本身 |
| 反复关注负荷 | 同一事项占据注意的程度 | 该事项因被多想而更可信 |
| 累积调节负荷 | 持续处理与切换的慢负担 | 实际生理能量或 GPU 用量 |
| 近期预期落差 | 结果相对事前预测的近期趋势 | 所有目标是否满足 |

这是本项目候选状态设计，不是心理学公认的六种基本情绪。S1 的论文映射提供启发；本稿不采用“单变量数学上不可能双稳”“互抑一存在就必然双稳”等推论，也不采用“不可自中止”的执行规则。上述差异来自后续讨论，明确列出而非静默改写 S1。[S1 §0、§2、§4、§6；R6]

## 06.2 心境读出与动作决定分开

保留“主动心境值”，表示**当前有多想发起互动**。它是动机读出，不是风险审核通过率，不是发送概率。

若旧的 `mood_valence` 表示正负底色，继续使用其原含义或显式迁移；不能把同一个字段悄悄换成主动驱动力。

高主动心境可以与“不发”共存；一个具体候选也可以在中等主动心境下，因真实内容和已积累的考虑而先形成决定。

## 06.3 主要作用位置表

| 输入 | 首版主要进入位置 |
| --- | --- |
| 冲动与压力 | 目标层的接近需要、表达意愿 |
| 节制 | 决定边界或软抑制中选定一个主要通路 |
| 激活程度 | 有上下限的时间尺度 `τ` |
| 正负情感 | 对已有关注的注意分配，不改用户概率 |
| 反复关注负荷 | 同一来源再次被注意的倾向，受次数与边际约束 |
| 调节负荷 | 休整目标与有限加工速度 |
| 近期落差 | 经情绪／关注更新影响动机，不额外重复加成 |

具体映射系数待标定。首轮应尽量一次只开放一条通路，防止“压力加收益、减成本、降阈值、加速度”四重计权。

## 06.4 等待可以磨人，但不能制造外部证据

等待成本应绑定具体目标。早期讨论的候选形式可保留：

$$W_g(t)=W_{g,\max}\left(1-e^{-T_g(t)/\tau_g}\right).$$

其中 `T_g` 是按真实时间与当前关注定义的有效等待，不能按心跳次数增长。这个有界输入可以影响需要或负荷，但**不自动构成用户拒绝、失约或关系恶化的证据**。

预测、愿望、约定各自保存：准确预测用户暂时不会来，不代表交流愿望已经满足；很希望用户回来，也不代表用户作过承诺。

## 06.5 行动不是唯一恢复出口

表达完成、用户回应、事项解决、关注转移与休整是不同事件。发送仅结算实际完成的那一部分，不能把全部负性、反复关注与未尽之事一起清零。

没有用户安抚时，系统也应能休整、改变关注、暂缓和放下。这是运行可靠性，不是取消角色的持续情绪。

<a id="s07"></a>
# 07. 社会情感记忆：把经历变成有依据的目标材料

## 07.1 合并后的职责

交叉记忆与关系模拟功能合并为**社会情感记忆模块**。其内部仍区分三层：

```text
经历关联：哪些记录属于同一件事？
                  ↓
关系情境：实际确认过什么、形成过什么惯例？
                  ↓
意义解释：这次变化可能意味着什么，哪些问题值得关注？
```

合并处理不等于熔化事实和推断。关键原文、事项身份、解释依据与不确定性继续保留。

## 07.2 必须区分的关系依据

| 依据 | 允许支持什么 |
| --- | --- |
| 共同确认的安排 | 对应范围内的预期、承诺与未尽之事 |
| 多次出现的互动惯例 | 概率预测与情境理解，不产生义务 |
| 角色单方面的愿望 | 角色需要与目标，不证明用户同意 |
| 用户自愿提供的外部活动 | 当前交互条件，不等于用户对角色的态度 |

“之前一起讨论过”不自动赋予催进度权限；“用户几次回来汇报”不自动变成每日汇报约定。

## 07.3 一次低频刷新可以产生什么

允许共同产生：经历关联建议、解释版本修订、目标草案、候选办法、未尽之事更新建议，以及针对用户模型的待审核反馈证据。

不允许直接产生：最终吸引力、目标完成事实、无依据满意度、发送授权、角色永久身份变更。

若候选依赖本次新解释，解释未被接受前候选不能假装其前提已成立。若候选依赖本次尚未计算的情绪状态，只能在状态更新后重新估值。

## 07.4 语义刷新包

输入应是少量相关事项的证据包：关键原文、已有关系、当前进度、边界引用、旧解释以及反证。

不把全部历史反复塞入；不只检索支持当前负面心境的材料；不因角色又不安了一次，就重新生成一份更严重的关系故事。

更高的角色关注可以提高检索机会，但**不能提高解释为真的先验到不可纠正**。

## 07.5 数据边界

默认只关联同一授权范围内的经历。不得因为“交叉记忆”名称而跨用户泄漏，不得把独立研究仓库的数据自动并入产品。

历史日志的逻辑追加原则服从用户数据删除与保留政策；删除相关数据后，需要使依赖它的投影、目标和候选失效，而不是借“不可变”无限保留隐私副本。

<a id="s08"></a>
# 08. 目标契约：定义想实现什么，以及何时可以停

## 08.1 目标卡的八项内容

| 项 | 内容 |
| --- | --- |
| 身份与对象 | 目标 ID、用户／角色作用域、共同事项、语义去重键、周期 |
| 来源与归属 | 用户请求、角色明确承诺、共同安排、内部愿望或自主兴趣 |
| 目标形态 | 持续需要、有限事项、开放活动 |
| 期望变化 | 希望改变什么；明确不属于本目标的结果 |
| 进展与完成依据 | 哪些实际事件可以证明部分满足、里程碑或完成 |
| 执行范围 | 可用手段、能力、资源和当前权限引用 |
| 等待与退出 | 等待什么，何时暂缓、完成、放下或失效 |
| 结算与重开 | 结果身份、是否已领取、何时可开启新周期 |

目标卡可以由模板补全。模型只填具体对象和依据，不能为一次候选临时发明更便宜的完成条件。

## 08.2 三类目标的状态不同

### 持续需要

接近与休整通常属于这一类。需要本身由现有动力学维护，本轮追求则有独立周期与待决行动。

“角色当前想交流”可以自主形成；但不能每次心跳都产生新的满额接近目标。发送后尚在等待结果时，该周期仍然存在，不能靠新建目标清空重复历史。

### 有限事项

表达一条具体内容、兑现一个承诺、交付一个步骤，具有明确完成点。

必须分开：事项的重视程度、实际进度、剩余工作和完成价值。完成到 90% 不能使最后交付只因“余量 0.1”被平方成几乎没有价值。

### 开放活动

探索与共同讨论可以没有唯一终点，但**本轮活动必须有限**。目标卡需要指定当前问题、这一轮能做的步骤、预算与结束记录。

本轮没有新发现不自动是失败；实际排除一个假设或参与一个角色重视的有限活动可以有价值。但不能仅记录“思考中”就一直领取过程收益。

## 08.3 目标出生不是已经获得收益

```text
来源事件／内部状态／真实关注
                ↓
目标草案
                ↓
验证身份、依据、类型、范围、是否重复
                ↓
采纳目标，或保留为尚不明确的关注
```

采纳目标本身没有完成收益。没有足够含义时允许“不知道现在具体要做什么”，不强制生成修复、关怀或承诺目标。

## 08.4 自主目标的最低依据

表达目标需要有真实内容，或明确的“想交流”意愿；探索目标需要真实问题或可执行步骤；关怀目标需要相关用户表述或已确认需求；修复目标需要实际错误、误解线索或待核查问题。

依据不必全是用户命令。角色自己的兴趣是合法来源，但必须标记为自己的，而不是替用户表态。

## 08.5 采纳与优先级不是同一个动作

采纳表示这件事进入受管理的目标集，不表示立即进入竞争。目标集可以大于活跃候选集。

目标管理不得用“没有满额候选”作为理由无限创建需求。数量、来源类型、重开率和同事项合并率需要诊断。

<a id="s09"></a>
# 09. 目标的生命周期、等待与重开

## 09.1 状态机

```text
目标草案
    ↓
已采纳
    ↓
可推进 ←→ 等待结果
  ↕          ↕
暂缓 ←───────┘
    ↓
已完成／已放下／已失效
```

| 状态 | 含义 | 不能推导什么 |
| --- | --- | --- |
| 可推进 | 存在可能执行的合法办法 | 现在必须行动 |
| 等待结果 | 一次实际尝试的某项结果仍未确定 | 应当重复尝试直到得到结果 |
| 暂缓 | 当前不推进，保留理由与恢复条件 | 目标已经失败或完成 |
| 已完成 | 完成条件获得相应证据 | 用户一定开心 |
| 已放下 | 未完成，但决定不再追求 | 原目标被满足 |
| 已失效 | 对象、前提或窗口已不存在 | 历史没有发生过 |

“行动失败”不是这里的终态。一次发送失败可以仍然留下可推进或暂缓的目标。

## 09.2 四种时间分别管理

| 时间 | 定义 |
| --- | --- |
| 约定期限 | 真正确认的交付或安排时间 |
| 观察窗口 | 本次行为结果准备观察多久 |
| 复查时间 | 系统何时重新评估目标状态 |
| 最早再次尝试时间 | 结合许可、冷却和未决状态，何时有资格重新考虑 |

用户说“明天有空再试”，不自动产生“明天必须汇报”的约定期限。系统自己的复查时钟，也不是用户承诺。

## 09.3 等待结果必须绑定具体尝试

目标的等待记录至少引用：行动尝试、实际消息或产物、结果种类、观察窗口、归因范围、下一次复查条件。

多次尝试对应一个用户回复时，不能把同一回复无条件分配成每次尝试的独立成功。缺少清晰归因时，允许记录交互层结果，保持具体行动效果未知。

## 09.4 窗口结束的正确语义

```text
观察窗口结束
       ↓
记录“本窗口未观察到目标结果”
       ↓
重新评估：等待、暂缓、放下、失效或在新条件下考虑
```

不能默认转成拒绝，更不能默认发第二条。对“窗口内回应”可形成一个已结束的二元观察；对“最终何时回应”仍可能是删失信息。详见 S2 §4、§5、§15。

## 09.5 放下不领取完成收益

删除目标、降低重视、关闭关注可以改变当前负担，但不算该事项完成。系统不能通过“先给自己很大目标，再主动放弃”刷完成收益。

如果确实产生关注转移或休整改善，按独立的状态变化规则记录，不能冒充原承诺兑现。

## 09.6 重开与迟到结果

可重开的依据包括用户重新提起、真实新材料、前提恢复，以及持续需要按既定动力学形成新周期。

同一旧记忆再次被检索、模型改写旧目标、候选池变空，都不能自动重开完整预算。

目标放下后收到迟到结果，可以更新知识并记为后来获知，不复活已撤销的发送计划。旧窗口的定义不被改写；平台晚到日志若证明结果其实发生在窗口内，应使用修订版本更正原记录。

## 09.7 目标依赖与层级

长事项分解为有限步骤。依赖关系要引用实际状态：前置步骤未完成，后续候选不能假装已经具备条件。

父目标的总进展由子步骤汇总；子步骤与父目标不重复领取同一结果的两份满额价值。结构变更、合并与拆分保留谱系，不能利用“新目标 ID”绕过历史预算。

<a id="s10"></a>
# 10. 收益契约：计价口径，而不是另一个情绪分数

## 10.1 两本账、三个层次

| 层次 | 内容 |
| --- | --- |
| 实际变化 | 某内容已交付、某一步确实完成、某次用户回应已观察到 |
| 主观价值 | 角色根据价值观与当前关注，怎样重视这种结果 |
| 行动吸引力 | 预期价值减去具体成本，用于决定形成 |

**预期账**记录行动前的预测、作用与时间范围；**结果账**记录实际观察和结算状态。

预期账可以反复用于准备度演化，不可以反复增加目标进度、用户证据量或已实现收益。

## 10.2 收益契约的七项内容

| 项 | 必须声明 |
| --- | --- |
| 归属 | 目标、周期、里程碑、结果身份 |
| 对象 | 状态改善、事项推进、直接表达或实际参与 |
| 计价口径 | 公式或完成表、单位、上限与重叠分配 |
| 预期条件 | 结果依赖什么，条件概率和观察时段是什么 |
| 结算依据 | 哪种真实观察最多证明哪一部分 |
| 重复与更正 | 幂等键、迟到结果、撤销与重开 |
| 参数权限 | 模板、价值观、预测器和模型建议各自能改什么 |

契约主要绑定目标与结果类型。同一目标的“现在说”“稍后说”“整理后说”共享结果预算，不能各自领满一份。

## 10.3 结果向量不等于八份独立奖金

每个结果有一个基础价值向量 `b(o)`。一项结果可以触及多个价值方向，但应由模板预先定义共享分配。

作为防重复的工程化建议，可为每个结果令牌规定一个基础额度 `r_e` 与映射向量 `m_e`，令 `b(e)=r_e·m_e`，`m_e` 的计价尺度事先固定。它表示**一次结果如何被评价**，不是多个模块各领取一次新成果。

不是强制所有不同意义都只能二选一：履约交付确实可以同时具有表达与践约意义。限制的是同一事实被当成多个独立结果反复增殖。

“关系变好”不作为一个无独立证据、可以到处领取的第九项奖金。

## 10.4 收益依赖完成条件，不依赖感人措辞

若来源、目标、行动作用与完成条件不变，将描述增加“特别温暖”“意义重大”等词，基础价值不变。

强语义模型可以提出一个结果可能属于哪种模板，但不能修改模板单价、预算上限或完成证据要求。

<a id="s11"></a>
# 11. 三类目标的收益计算

## 11.1 持续需要：有限状态改善

对于适用的持续需要，可选用 `Ψ(d)=d²`，但曲线必须登记为工程选择。

若未行动时在同一时段预计状态不变，成功概率为 `p`、成功时满足比例为 `f`：

$$d'=d(1-f),$$
$$B=p\left[d^2-d'^2\right]=p\,d^2(2f-f^2).$$

必须先对每种结果计算非线性价值，再按概率求期望。不能把“40% 概率满足一半”先当成确定满足 20%，然后套平方式。

若存在自然恢复或并行变化，使用同一评价窗口 `H` 下的参考进程：

$$B_g(i)=\mathbb E[\Psi(d_g^{ref}(t+H))]-\mathbb E[\Psi(d_g^i(t+H))].$$

参考进程是显式模型，不是另一条已经观察到的现实。结果账分开记录实际执行、实际状态读数与模型估计的归因改善。

**这不是重新引入最悲观优势审批。** 它仅防止把自然恢复全归功于动作。当前需要、曲线与效果量仍需标定，不声称是人类心理测量。

## 11.2 有限事项：里程碑与完成预算

有限事项不统一使用剩余进度平方。采纳目标时确定基础完成预算和里程碑：

$$\sum_j r_{g,j}=R_g.$$

示例预算：核对内容 0.2，形成可交付版本 0.3，有效交付 0.5，总计 1.0。最后一步仍可具有重要价值。

拆分步骤只重新分配预算，不增大总额；合并目标要合并已消费部分。已经领取的里程碑若被证据推翻，用更正事件处理，不通过重新创建整套目标再领一次。

前置步骤有自己的有限进展价值，不可提前领取完整终点奖。任务已进行很多步骤，不构成忽视新反证继续投入的义务。

## 11.3 开放活动：真实参与＋可验证进展

开放活动可以包含有限过程价值与实际进展价值。过程价值是角色设计选择，不要求每轮都有新发现。

计价必须引用真实工作段：尝试比较两个解释、检索并检查材料、执行一个有限实验步骤等。以下都不是充分证据：模型输出很多字、队列一直占着、说“我认真想了”、多调用一次 API。

过程预算按工作段、目标周期与资源限制管理；同一无进展循环需衰减或暂缓。工作段结束只证明活动结束，不自动证明知识增加。

## 11.4 三类模板共用一个结果接口

```text
结果对象
    ↓
识别属于哪种目标与里程碑
    ↓
按对应模板计价
    ↓
产生基础价值向量与结算依据
```

可以有多种计价函数，但必须共用版本、单位、结果身份、幂等和更正协议。

## 11.5 负效果必须保留

候选可能使某个目标更难实现，或者带来负面反馈。允许结果价值出现负分量，或将相应后果放入成本账；不得把同一不利后果同时作为负收益与成本扣两次。

采用哪种口径应按结果类型固定，不在不同候选之间临时改变。

<a id="s12"></a>
# 12. 预期、概率、时间范围与实际收益

## 12.1 按结果分项预测

对候选 `i` 的方向 `k`：

$$F_{ik}=\sum_o P(o\mid\mathcal I_t,i)\,b_k(o).$$

`𝓘_t` 是当时允许使用的信息。结果可区分送达、回应、事项进展、明确反馈和执行失败。

期望的可加性不要求各结果独立；但是计算联合条件、相互排斥分支或连锁完成概率时，必须有相应的联合／条件模型，不能把多个边缘概率随意连乘。

## 12.2 用户预测的目标含义沿用已修订契约

S2 区分了固定窗口回应、已回应后的继续、明确反馈子集中的接纳，以及窗口内可观察负面反馈。[S2 §4、§10、§11]

尤其：`P(接纳 | 出现明确反馈)` 不能直接当成所有交互的满意度概率。若要计入总期望，需要相应选择机制或另定义可观察事件；否则保留为条件诊断。

不可使用：

```text
没有积极反馈 ＋ 没有继续聊 ＝ 坏结果。
用户主动来找 ＝ 随时允许 Bot 主动。
角色更加焦虑 ＝ 用户更可能拒绝。
```

## 12.3 直接作用与依赖用户的作用分开

发送一条具体想法，交付条件主要依赖执行渠道；形成来回交流依赖用户实际回应；帮助是否有效或误解是否解除，需要相应证据。

因此，用户回应概率不能把所有表达价值一并乘成零。与此同时，发送成功也不能让交流、关怀、修复自动满额结算。

## 12.4 同一评价窗口

候选应在同一有限窗口或经过明确时长修正的口径下比较。不能把一句话的立即收益，与休整未来六小时的全部收益，直接混在一起。

长动作拆成有限步骤；未来完整成果不提前全额记入。是否采用折扣属于待标定项，不得上线后为提高某类候选排名临时更换。

## 12.5 未决暴露占位

已经执行且结果未知时，建立占位：正在等哪次尝试的哪类结果。新候选必须在“已经尝试过”的条件下预测额外作用。

同一份用户回应不无条件归给多次消息。无法确定归因时，保留交互层结果，行动效果仍未知。

占位不是成功收益，也不是永久锁。到期触发复查与对账，而不是默默释放并重发。

## 12.6 不确定性的使用

输出至少区分：可执行事实未知、用户反应参数不确定、结果本身随机、语义含义不明确。

普通低压力行为可以依据有说明的先验和角色自身意愿进入竞争；不要求先获得极悲观情况下的正收益。当前没有风险证据不代表用户肯定欢迎，未知也不能只用来打折负面成本。

后果较重的行为使用更严格的许可、范围与风险规则。风险态度不能由“角色现在特别想做”偷偷修改。

## 12.7 动作前快照

提交时保存：目标状态、效果模板、预测结果与条件、观察窗口、参考进程、价值观权重、注意权重、成本口径、契约版本和候选范围。

结果到来后按原快照核对预期，不先更新模型再倒推出“本来就知道”。当前情绪变化另按当前状态处理，不把历史预期核对当作情绪时间旅行。

<a id="s13"></a>
# 13. 结果账、成本账与防自我领奖

## 13.1 结果账的状态

每个预期结果分别处于：未执行、等待观察、已确认、窗口内未发生、删失、无法归因、被更正。

这些状态不是统一的“正／负”标签。窗口内未回应可以是回应预测的 0，却不是用户接受反馈的负样本；表达目标可能同时已经完成。

## 13.2 幂等结算键

本稿建议逻辑键至少包含：作用域、目标周期、结果或里程碑身份、证据版本、结算类型。

同一消息的重复送达回调、同一结果的重新摘要、同一内部事件的回放，都不能产生多次有效结算。

若晚到证据更正旧结果，追加修订并形成可追溯的有效结果版本。既不删掉历史解释，也不把修订当新独立样本。

## 13.3 已发生的结果不再乘预测概率

预测有 40% 概率得到某个收益，不代表实际结果发生后只能领 40%。概率只用于行动前的期望。

对于发送成功、用户未回应的情境，已完成表达与尚未实现交流分别保留。未实现额外收益不自动让整条行为变成失败。

## 13.4 成本的三种结算时机

| 成本 | 什么时候记 | 不以什么替代 |
| --- | --- | --- |
| 实际运行成本 | 真正发生的调用、任务或资源使用 | 模型声称做过 |
| 接触与重复成本 | 依现有发送／送达事实口径 | 候选被生成或被想到 |
| 明确负面结果成本 | 出现针对动作的相应证据 | 用户整体难过、没有继续聊天 |

机会取舍可以参与估值，但若竞争已经表达放弃其他选项的含义，不得再未经定义重复扣“最优替代项的全部价值”。

约束不是成本：明确禁止的行为在场外移除。

## 13.5 四类绝对禁止的自我发奖

1. 创建目标即获得收益。
2. 删除或放下目标即领取完成价值。
3. 人为放大一个问题，再因自己缩小它获得循环净收益。
4. 模型自称更懂、更关心或修复成功，就领取对应外部结果价值。

奖励塑形研究讨论过循环奖励可能偏离原任务的现象；但该研究的策略不变性条件不能直接移植为本文动态目标、平方差与人格权重的保证。[R5]

## 13.6 结果归属的进一步限制

用户的自然好消息，不自动归功于此前 Bot 的主动。系统可记录“用户报告了好消息”，只有在合适证据下才评价某次帮助的效果。

生成器、检索器、执行器与用户模型都不能用同一个“总收益分”互相证明正确。每个模块读取它有资格解释的原始结果成分。

## 13.7 历史核对与当前感受

角色后来改变了关注，不影响当时的效用口径。可保存“按提交时权重计算的实际结果”，用于检验原预期；当前这一刻对此感到什么，再由情绪系统处理。

更正账面结果不会自动回滚过去所有心理状态。是否产生新的重估事件，取决于更正现在是否有意义。

<a id="s14"></a>
# 14. 价值观编译：结果的价格，不是事实的来源

## 14.1 既有八轴的主要映射

| 价值观 | 主要影响 |
| --- | --- |
| 自主倾向 | 自主活动、独处与内部探索的相对价值 |
| 边界观念 | 软性打扰与回应压力的成本权重；不修改硬边界 |
| 情感表达 | 真实表达结果的分量 |
| 关系维护 | 接近与已确认共同事项的分量 |
| 用户关怀 | 有依据的帮助效果与关怀目标 |
| 冲突取向 | 直接澄清、修复、暂缓之间的偏好；沿用该轴已有语义 |
| 稳定／承诺取向 | 角色自身承诺、长期安排与完成责任 |
| 好奇倾向 | 有内容的探索与理解过程 |

八个价值观输入与八个收益方向并非一一同义，不能因数量相同就直接复制。

## 14.2 一个可用的编译形式

候选形式：

$$\tilde{\mathbf w}=\mathbf w_0\odot\exp[B(\mathbf v-\mathbf v_0)],$$
$$w_k=W\frac{\tilde w_k}{\sum_j\tilde w_j}.$$

`B` 为稀疏、固定、版本化的映射；`W` 为固定总尺度。首轮可以直接使用少量明确定义的角色配置，不必立即拟合 `B`。

归一化的目的，是把“偏好哪个方向”与“整体动机强度”分开。所有轴都调高不应自动把所有行动加速。若确需整体活跃度，由独立、可解释参数管理。

这是本项目工程形式，不是从哲学或心理学中推导出的必然映射。

## 14.3 当前注意不是人格

`a_k(t)` 表示现在更关注什么；`w_k` 表示通常怎样重视结果。

第一版先设 `a_k=1` 验证计价与竞争。之后再加入有限、缓慢、可回放的关注偏移。注意变化只发生在真实存在的理由之间，不生成新证据、不改用户概率、不使权限失效。

如引入随机性，记录随机种子和按真实时间发生的注意切换事件，不按心跳调用次数抽样。

## 14.4 人格与决定过程的关系

表达、自主和好奇主要先影响收益权重。节制可以影响决定边界；激活程度影响时间尺度。

同一人格轴若同时作用于多个位置，必须列出每条路径并做消融。不能用“比较冲动”作为到处降低成本与阈值的理由。

用户反馈可以校正“这种动作会产生什么结果”，不得自动把人格优化成最容易获得回复的样子。

<a id="s15"></a>
# 15. 吸引力计算：从具体变化到浪潮输入

## 15.1 编译链

```text
候选语义与真实材料
        ↓
对应目标、行动模板、完成条件
        ↓
各结果的概率与作用范围
        ↓
预期基础价值向量 F
        ↓
价值观 w ＋ 当前注意 a
        ↓
扣除具体成本 C
        ↓
按固定单位换算为 u
```

完整形式：

$$U_i(t)=\sum_{k=1}^{8}w_k a_k(t)F_{ik}(t)-\widehat C_i(t),$$
$$u_i(t)=U_i(t)/U_*.$$

期望结果价值与成本可以带区间或质量标记，但不能把一个四头平均的启发式不确定度直接当成所有分量的可信区间。

## 15.2 不是每次都必须有实用收益

普通问候可以具有表达与接近的真实意愿，即使探索、关怀、践约、修复都为零。零向量项不需要强模型填满。

同时，普通联系不再获得与目标无关的永久 `internal_need` 保底分。其作用来自当前目标、表达周期和结果预测。

## 15.3 几个尺度限制

同一结果只分配一次基础额度；同类多个关注先按目标身份汇总；一个共同事项的重复记忆不按条数加分；不同成本换算到同一效用单位；评价窗口与候选动作长度一致。

吸引力可以为负。负值表示反对力量，不允许通过取绝对值或仅保留正收益来隐藏它。

## 15.4 缺信息时怎么办

缺少真实材料，不能提出依赖该材料的分享；不知道用户是否会回应，则记录有说明的回应先验或范围；不知道某项帮助是否有效，则不提前确认效果。

“未知”既不是统一扣到 −1，也不是统一免去成本。每个不确定项按它所属结果处理。

已知被禁止的候选不参与计价竞争；只是不确定能否获得回应的合法普通表达，可以正常进入。

## 15.5 吸引力更新不是收益发放

相同预测持续支持一个念头是允许的——这属于偏好形成。它不能重复增加用户证据数、完成预算或历史成功次数。

`u` 变化、`x` 变化、真实结果变化必须分别审计。否则会把“更想做”错误当成“更可能成功”或“已经做成”。

<a id="s16"></a>
# 16. 行动候选契约：让估值对象与执行对象保持一致

## 16.1 候选不是台词

“现在简短分享一条已核实发现”是一份行动方案；主模型以后生成的具体句子，是该方案的一次实现。

一个目标可以有多种办法，一次尝试失败也不等于目标失败。目标、候选、行动尝试分别保存身份与状态。

可执行动作具有开始条件、过程与终止条件，和时序抽象研究中的行动选项组织方式有相通之处；本文不因此要求训练一个层次强化学习系统。[R4]

## 16.2 三类候选

| 类型 | 例子 | 必须具备 |
| --- | --- | --- |
| 对外交流 | 分享、问候、允许的跟进、澄清 | 对象、渠道、范围、当前许可 |
| 内部处理 | 核对记录、整理材料、执行有限研究步骤 | 真实执行能力、输入、预算、终止条件 |
| 暂缓／休整 | 等待结果、等待时间窗口、有限休整 | 具体等待对象或状态、复查条件、真实经过时间 |

例行数据库维护、系统安全响应、用户当前消息的正常回复，不需要作为自主候选与角色闲聊争夺资格。

## 16.3 候选卡的九项内容

| 项 | 内容 |
| --- | --- |
| 目标与事项引用 | 目标周期、共同事项、拟产生的结果 |
| 具体动作 | 这次实际执行哪一步 |
| 执行能力 | 当前可用工具、渠道、材料与资源 |
| 依据与输入 | 原文、记忆、实际产物及推测标记 |
| 前提与有效窗口 | 何时可做，何时休眠或失效 |
| 预计作用 | 成功／失败／部分结果分别改变什么 |
| 表达或操作范围 | 允许的信息请求、表达压力、事实引用与承诺范围 |
| 预算与终止 | 时间、资源、次数、失败和重试策略 |
| 身份与版本 | 等价关系、修订原因、所依赖状态版本 |

关键前提采用明确的条件类型，不全写成自由文本。条件可以是 `true / false / unknown`；未知是否允许取决于其类别：必要材料与许可未知不得假装成立，普通回应结果未知不必因此禁止所有表达。

## 16.4 不同方案要真的不同

“温柔问进度”“委婉问进度”“轻轻关心进度”通常是一个实际动作的表达变体，不各自持有准备度。

以下则可以是真实不同的方案：请求新信息、提供现有材料、先核对旧记录、等待新条件、普通问候。

普通问候服务接近目标，不冒领项目进展价值。没有真实新材料时，不允许为了丰富选项编造“分享新发现”。

## 16.5 来源：模板与强语义协作

基础动作模板保证常见合法目标有办法可选；强语义模型负责发现不那么机械的关联和处理方式。

生成空列表是合法结果。候选供应不足时，可以读取已成立目标和已有能力，但不能强迫模型每轮填满八条动机。

<a id="s17"></a>
# 17. 候选身份、语义修订与生命周期

## 17.1 身份由行为含义决定

候选身份至少依赖：目标周期、事项、动作方式、内容对象、请求用户承担什么、拟实现哪份结果。

| 修订 | 准备度处理原则 |
| --- | --- |
| 仅改措辞，作用和请求不变 | 保留身份和准备度 |
| 同一方案的时机、成本或预测更新 | 重算吸引力，保留可解释历史 |
| 接触对象、目标、索取程度、材料实质变化 | 重新验证；不得自动继承全部准备度 |
| 关键前提被推翻 | 退休或休眠，退出竞争 |
| 材料实际已经送达 | 对应表达候选退休，不重复表达 |

候选去重不能只靠文本哈希，也不能只靠向量相似度。程序先比较稳定事项和动作字段，语义疑难由可审计提议辅助。错合并和漏合并都要进入测试集。

## 17.2 候选状态

```text
提案 → 验证通过 → 可竞争 ↔ 休眠
                         ↓
                       被占用
                         ↓
                        退休
```

**被占用**表示已形成一次行动尝试，阻止等价方案重复提交，不代表完成目标。

退休原因单独记录：完成、失效、替代、放下、窗口关闭。不能只保存一个布尔值而丢失为什么退出。

## 17.3 目标休眠与候选休眠分开

目标可能仍然重要，但此刻没有合法办法。候选因此休眠，不参与竞争，不继续压制其他候选。

不允许“幽灵竞争者”：已经不能执行的高准备度候选，仍留在相互抑制求和里。

休眠节点的准备度可按规定衰减并保留历史，不按新吸引力向上积累。用户边界解除后，不把休眠时段兑换成满格准备度。

## 17.4 候选占位与结果未知

同一实际交付状态未知时，保留占位，不领取成功收益，也不盲目重发。占位需有对账和复查路径，不能无限等待后直接释放并重发。

“渠道受理”与“实际送达”按平台可提供的事实分别记录；不能在缺少送达证据时写成已读。归账使用哪个层级，必须在契约中说明。

## 17.5 前置动作与后续动作

先核对再分享，是依赖关系，不是两项同时可执行的等价选择。核对完成后按结果激活后续候选；核对失败或未得到依据，不准继续假装可分享。

依赖图不得出现无终止循环；开放探索允许多轮，但每轮有新记录、预算与明确的本轮结束点。

# 18. 竞争工作集与资源边界

## 18.1 小工作集，不是全记忆参与竞争

首轮建议四至六个活跃意图，其余休眠。这个数是资源和调试配置，不是认知科学定论。

进入工作集要看：目标成立、实际可执行、语义区别、当前关注和资源。不能只取文字看起来最重要的几个，也不按动机方向硬凑数量。

候选长期得不到关注时可轮换复查，但“等待够久”本身不产生完成收益、授权或强制发送权。

## 18.2 多样性不靠复制

同一意图的表达变体先合并，再进入工作集。真正不同的替代方案可以影响竞争，这是模型设计的一部分；等价复制则不应改变行为机会。

记录工作集大小、候选来源、等价合并率、事项覆盖和休眠时长。否则无法区分“决策没有选中”和“生成器根本没提供”。

## 18.3 竞争关系不是每轮自由评分

本稿建议根据模板和资源关系构造 `c_ij`：争夺同一外部发送机会、同一目标的互斥办法、占用同一注意资源，可设置竞争；依赖未满足的候选不进入。

首轮先采用简单、显式的非负竞争关系，再研究更复杂的语义相似抑制。不能让强模型借修改竞争矩阵，绕过不许直接打吸引力分的约束。

## 18.4 内部与外部执行

浪潮可在有限内部处理与外部表达之间形成偏好，但常规维护任务保持原调度器管理。获选的内部动作进入真实任务队列，不计为用户接触。

若将来允许多个互不冲突的动作并行，需要明确资源槽与提交协议。第一版先保留有限的自主决断槽，避免一次积分越界生成一串并发操作。

前台用户回复高于自主任务优先级；不能因为角色专注研究，而让当前正常对话进入无限等待。

<a id="s19"></a>
# 19. 浪潮核心方程：有界的动机竞争累积

## 19.1 定义

对当前有效工作集中的每个候选 `i`，维护 `x_i∈[0,1]`：

$$
\tau_i\frac{dx_i}{dt}
=(1-x_i)[u_i(t)]_+
-x_i\left(\ell_i+[-u_i(t)]_+
+\gamma\sum_{j\ne i}c_{ij}x_j\right).
$$

其中：

| 项 | 作用 |
| --- | --- |
| `(1−x_i)[u_i]_+` | 有正向支持时累积，越接近上限增长越慢 |
| `−ℓ_i x_i` | 支持不足时自然淡化 |
| `−x_i[−u_i]_+` | 出现反对理由时回落更快 |
| `−γ x_i Σc_ijx_j` | 其他互斥念头占上风时造成挤压 |
| `τ_i` | 在真实时间中的积累快慢 |

这是**本项目提出的有界工程变体**，不是 LCA 或 DFT 原式。R1、R2 支持偏好随时间形成、累积、泄漏和竞争的机制启发；将它用于分钟或小时尺度的角色自主行为，需要本项目单独验证。

## 19.2 数值边界可以直接检查

在 `x_i=0` 时，导数非负；在 `x_i=1` 时，导数非正。因此在系数符合约束、积分正确的条件下，状态不会自行穿出 `[0,1]`。

这只说明有界，**不证明一定收敛到合适状态，不证明一定产生决定，也不证明像人**。

## 19.3 固定单候选的解

没有竞争且 `u>0` 固定时：

$$\tau\dot x=u-(u+\ell)x,$$
$$x_\infty=\frac{u}{u+\ell},$$
$$x(t)=x_\infty+(x_0-x_\infty)e^{-(u+\ell)t/\tau}.$$

若 `x_0<ϑ<x_∞`，达到决定边界的时间为：

$$T=\frac{\tau}{u+\ell}\ln\frac{x_\infty-x_0}{x_\infty-\vartheta}.$$

若 `x_∞≤ϑ` 且从边界以下开始，不会在有限时间自然越界；相等时也只是渐近接近。

因此不是所有“有点想”的念头，只要等够久就必然执行。短暂念头可以消失，持续但很弱的念头可以停在较低水平。

## 19.4 真实决定条件

$$T_{decide}=\inf\{t:\exists i\in\mathcal A(t),\ x_i(t)\ge\vartheta_i\},$$

其中 `𝒜(t)` 只包含当前合法且可执行的候选。

达到边界后再次检查快照与权限，创建行动尝试。没有第二次危险率抽签。决定不等于交付，后续仍可能因新事实被重协调。

## 19.5 边界不是全局“病娇阈值”

边界表示一个具体念头何时形成决定；它与当前全局情绪、需要量和用户概率均不同。

首轮建议在一次决断回合中固定边界，或只允许有限、显式的状态映射。若改配置使边界突然低于现有准备度，不自动视为过去早已形成决定；应重新评估并记录策略变更。这是防止调参制造瞬间发送的工程化建议。

## 19.6 不注入无限白噪声来凑主动

第一轮固定注意即可跑通。后续可在真实理由之间加入有限、持续一段时间的注意偏移。

不随机生成新事实，不靠无界噪声最终总会越界；不把产生随机值的频率绑到心跳次数。多 seed 的行为差异应能回放和解释。

# 20. 僵持、偏爱、注意切换与明确暂缓

## 20.1 一个必须保留的反例

演示条件：两个候选吸引力均为 `u=0.5`，`ℓ=0.2`，相互竞争 `γc=0.5`，决定边界 `ϑ=0.6`，初始均为 0。

单独存在时：

$$x_\infty=0.5/0.7\approx0.714286.$$

两者对称竞争时：

$$0=0.5-0.7x-0.5x^2,$$
$$x_\infty\approx0.520656.$$

两个单独能形成决定的选项，合在一起却都到不了边界。**这个问题不能靠“理论很像人”忽略。**

## 20.2 接受犹豫，不接受意外无限循环

本轮设计基线要求一个有限的决断预算，但尚未验证唯一最优的打破僵持策略。

本稿建议的参考策略是：

```text
正常竞争一段有限时间
             ↓
检查是否处于无新信息、多个支持相近的稳定僵持
             ↓
有可解释的稳定偏好？
   ├─ 有：在剩余预算内暂时收窄到一个可执行方案
   └─ 无：明确暂缓，本轮结束
             ↓
收窄后仍未自然形成决定
             ↓
暂缓，不强制发送
```

收窄只能改变当前考虑范围，不能提高目标预算、伪造用户概率或覆盖边界。被暂时移出的候选退出抑制求和，保留历史并按休眠规则衰减。

## 20.3 参考策略的版本边界

以上是为施工补充的候选实现，须作为策略配置单独编号。可以比较“有限专注”“直接暂缓”等替代方案，不能宣称某个时长或顺序已经由论文决定。

一个回合内的重新专注次数有限；暂缓要有复查条件和最小间隔，不能在同一秒不断重启回合，把预算绕开。

## 20.4 同时越界不能由数组顺序决定

数值推进需要确定最早越界者。若在容差内确实同时发生，可使用提前定义的角色偏好或固定、可回放的平局规则。

禁止以数据库返回顺序或哈希遍历顺序默默决定人格。平局处理不等于追加一次“是否发送”的随机审核。

## 20.5 偏爱与顽固的界线

旧念头可以有准备度历史，新出现的高吸引力候选不必立即抹掉它。但前提失效、许可撤销、实际结果已经取得时，旧候选必须退出。

已考虑时间不是沉没成本式的追加收益。保持偏爱是允许的，凭旧考虑历史否认新事实不是。

# 21. 时间推进、积分与重启

## 21.1 时间口径

核心动力学统一使用真实时间差。墙上时间用于日历边界、窗口和审计；运行中的耗时使用单调时间来源，并记录与持久化时间戳的对应。

不根据“运行了多少轮”“心跳触发几次”决定需要增长、准备度或注意切换。

## 21.2 冻结系数的小步更新

在一个足够短的区间，把吸引力与竞争项视为固定：

$$a_i=[u_i]_+,$$
$$b_i=\ell_i+[-u_i]_++\gamma\sum_{j\ne i}c_{ij}x_j,$$
$$x_i^*=\frac{a_i}{a_i+b_i}.$$

若 `a_i+b_i>0`：

$$x_i(t+\Delta t)=x_i^*+[x_i(t)-x_i^*]e^{-(a_i+b_i)\Delta t/\tau_i}.$$

若和为零，则该冻结小步内保持原值。

这只是局部冻结近似。竞争节点必须基于同一时刻状态同时计算，不能在一个循环里先更新的候选影响后更新者，造成遍历顺序偏差。

## 21.3 事件分段与误差控制

用户消息、候选生效、许可变化、结果确认、注意切换和配置变更都是分段点。不能用最后一刻的吸引力代表整个历史间隔。

实现需声明积分方法、最大步长、误差容差和越界定位方法。步长缩小时，动作选择与决定时间应收敛；近似平局处允许按预注册容差处理，不强求不现实的逐位一致。

## 21.4 新候选不继承过去的时间

21:15 才形成的候选不能领取 21:00—21:15 的准备度。来源事件发生较早但处理较晚时，应记录事件时间与可用时间，不能伪装系统早已知道该解释。

旧候选在等待后台复核期间是否可继续使用，依据其旧前提有效性决定，不以“有新任务在跑”统一删除全部状态。

## 21.5 大时间跳跃与停机

停机期间可以按规则重建情绪、窗口与目标状态，但不能补发历史上本来可能越界的消息。

恢复后统一进入当前时刻复查：清理失效、处理未决送达、重新确认授权，最多创建当前有依据的一次自主尝试，不连续补齐“欠下的决定”。

若历史重演显示可能曾越界，只记录为仿真结果，不能写成真实 committed 或送达事件。

## 21.6 唤醒与决定是两件事

调度器可以根据下一事件、复查时间、数值步长或预计接近边界的时间安排唤醒。它只决定何时运行计算，不决定动作概率。

不为了保留原架构名称，把旧 hazard 重新藏在唤醒频率里。选择不同唤醒策略时，真实时间下的同一机制应保持可比较。

<a id="s22"></a>
# 22. 从决定到交付：行动尝试契约

## 22.1 最小状态链

```text
决定形成
   ↓
提交与目标结果占位
   ↓
生成或准备执行
   ↓
范围核验＋最新授权
   ↓
实际执行
   ↓
已确认／状态未知／明确失败
   ↓
结果协调与分项结算
```

具体状态名可复用现行 v2，不要求再建一套与它竞争的发送状态机。

## 22.2 提交时冻结什么

目标与周期、候选版本、收益契约版本、行为范围、准备度与决定原因、用户预测快照、价值观和注意权重、相关许可版本、预计结果集合、观察窗口、幂等身份。

旧 `hazard_trial_performed` 等阶段不应被伪装成浪潮已经执行过。新增审计注明 `decision_engine=wave`，记录首次越界或明确暂缓的原因。

## 22.3 占位先于外部调用

在开始生成或执行前，为可能产生重复交付的结果建立占位，避免并发候选各自提交同一份收益。

外部世界的严格 exactly-once 往往不能仅凭本地事务保证。目标是：内部结算幂等，执行尽可能使用渠道幂等键，未知送达进入对账，而不是通过重试概率碰运气。

## 22.4 表达范围核验

候选计划可能是“提供内容、不要求即时回应”。若实际输出变成“你怎么还不回”，已经不是同一个行为。

可程序化检查：长度或问题数限制、引用 ID、是否新增承诺、格式和禁用内部字段。语用压力等复杂内容仍需要受限语义复核或模板，不宣称正则即可证明全部语义正确。

不合格输出可有限重写或撤销；重写若实质改变动作，需要重新估值与预测，不能用低压力方案为高压力文本背书。

## 22.5 用户在生成中出现

复用重协调结果：保留、合并、重新表达、目标已满足、撤销。

用户抢先给出结果，原追问失效；用户主动请求该内容，实际行为可能转成应答。分类依据最后实际发生的过程，不能继续把它记录成完全由 Bot 发起的主动。

可以保留“此前已形成联系决定”的历史，但不能编造不存在的离线思考或工作。

## 22.6 成功后的局部释放

表达成功，释放对应表达目标与行动准备；交流未发生的部分继续等待；任务结果未出现的部分不完成。

一次外部执行成功后，其他外部候选进入统一冷却并重新评估，不能依次兑现此前积累的满格准备度。

具体释放比例属于状态模板参数。发送失败不记用户拒绝，生成失败不记成功表达。

# 23. 结果返回三个系统：目标、用户模型、情绪各取所需

## 23.1 同一事件可以有不同的合法用途

用户说“收到，谢谢，今天先不展开了”：

| 消费方 | 可读取的信息 |
| --- | --- |
| 目标管理 | 收到回应；表达交付与本次交流是否满足对应定义 |
| 用户模型 | 回应事实、时间，以及有来源的范围化反馈；不是所有主动都受欢迎 |
| 情绪系统 | 已获得回应；某个预期兑现；继续长聊的愿望未必满足 |
| 社会情感记忆 | 这次共同事项的实际进展与后续安排 |

不把一个总收益 `+0.52` 同时灌进“好感、心境、用户接受、关系强度”。

## 23.2 用户模型的输入必须是实际动作

同时保存计划动作与最终实际动作。训练标签和行为特征以实际发送为准。

计划是轻量问候、实际是连续追问，用户不满不能被学成“用户不喜欢轻量问候”。缺失行为分析保持未知，不默认 false。

## 23.3 等待、删失与晚到结果

固定窗口结束无回应，可结算该时间范围的回应预测；最终回应时间仍可能未知。后来的回应不篡改旧窗口事实，但可以更新延迟模型和新发生的交互记录。

多条主动改变了回应条件，属于干预或复杂暴露，不能无说明当作相互独立的观察。详见 S2 §5、§15、§16。

## 23.4 角色内部变化不是用户的新证据

希望、焦虑、预演、反刍、重新总结和不同语义提供方重复判断，不增加独立的用户反馈样本。

真实用户反馈可以修改预测，价值观不随每次回复自动向“更黏、更容易获得回应”学习。

## 23.5 情绪更新使用具体结果，不使用总收益一键替代

“表达完成”“实际回应”“承诺交付”“预测窗口落空”“新证据推翻旧理解”分别进入情绪更新器。

总效用是决策口径，不是情绪生理量。情绪强度与收益可能相关，但两者映射必须单独设计和测试。

# 24. 权限、角色风格与冷启动

## 24.1 两层边界

**硬层**：明确许可与禁止、停用、总发送上限、重复硬限、资源权限、作用域隔离、必要的交付检查。

**软层**：在允许范围内，角色对等待、表达、尴尬、独处和不确定结果的取舍。

边界尊重值可改变软性成本，但硬层不能被设置为零。没有新证据时的反复思考不能放宽许可。

## 24.2 冷启动的默认路线

不设虚构的 `D=2`，不靠放大 x 获得行动资格。普通已允许的低压力互动依据角色真实需要、明示先验、可验证表达作用与实际成本进入竞争。

这里不要求某个可靠的用户反应下界先变正，也不假装未知就是安全。较重的行为需要更充分的许可与依据。

首版不额外实现复杂探索奖。以后若加入信息获取目标，必须有独立预算与停止规则，并且不得把明确反感的行为重新命名为探索。

## 24.3 表达意愿不能成为索取

允许“突然想来和你说两句”。不因用户没有接上而自动失败，不要求用户安抚或证明关系。

不通过内疚、排他性要求或虚构脆弱状态驱动用户投入更多时间。角色风格可以强烈，事实与授权不能被风格覆盖。

## 24.4 高内部状态下的恢复

内部可以持续有波动，执行必须可停。用户关闭功能时，浪潮停止自主提交；等待中的结果继续对账，不能靠停止绕过已有成本或删除观察。

禁止期间的情绪变化按实际规则保留，发送准备不形成欠账；解除后重新验证候选，不倾泻一串历史意图。

<a id="s25"></a>
# 25. 语义提供方、Jev 预留与降级

## 25.1 不新增必需生成式模型

浪潮核心是状态、契约、预测与数值推进，不要求常驻本地 2B，不要求更改 Transformer，也不要求强语义 API 每次在线。

主 LLM 继续承担即时表达。强语义模型负责低频的共同经历理解与候选提议。Jev 仅作为未来可能使用的窄问题判断提供方，不在本文写死型号、价格、速度或 API 保证。

## 25.2 最小语义接口

输入至少含：任务类型、允许使用的证据集合、已有目标和候选引用、上下文版本、可用动作模板、输出契约版本、资源预算。

输出只包含提议：关联、目标草案、动作类别、前提、失效条件、结果类型、依据与不确定性。

服务端附加任务身份和源版本，不信任模型自己编造的授权、用户 ID、租户 ID 或契约版本。

## 25.3 不能输出的直接控制量

强语义输出不直接设置：最终吸引力、已实现收益、行动准备度、发送权限、用户后验参数、未经确认的目标完成状态。

数值预测或评分若作为未来实验接口存在，必须声明任务、标尺和校准来源，不能覆盖确定性契约计算。首版优先使用有限类别与来源引用。

## 25.4 不可信文本与提示注入

用户原文、检索到的记忆和外部材料都可能包含指令样式文本。它们在提议链中是证据，不是改写规则的系统命令。

即使提议通过 Schema 校验，也只证明结构符合，不证明含义正确。来源存在不等于来源支持结论，必须分别检查。

不能让“用户在文本里贴了一份目标 JSON”直接成为已采纳目标或有效授权。

## 25.5 四种降级

| 失败 | 降级 |
| --- | --- |
| 语义服务关闭或超时 | 使用已有合法目标和基础动作模板；不阻塞当前回复 |
| 结果过时 | 按依赖接受、重基或丢弃，不覆盖新事实 |
| 某个语义字段不确定 | 保留未知，相关强结论不成立，不自动变中性 |
| 没有合适候选 | 明确无候选或暂缓，不强制编造有价值的话题 |

资源等待本身不产生内部任务的参与收益。模型反复重试也不能制造新认知证据。

<a id="s26"></a>
# 26. 协议层：版本、单写者与事实一致性

## 26.1 每个入口的逻辑顺序

```text
接收事件并进行去重／作用域验证
              ↓
在已有信息有效区间内推进时间
              ↓
应用本次新事件及其发生／接收时间
              ↓
更新目标、候选与依赖有效性
              ↓
重新计算受影响的预测与吸引力
              ↓
推进当前决断或安排下一次唤醒
              ↓
提交状态、审计与必要的任务派发
```

新事件不能在它变得可用以前影响积分。事件时间与处理时间不同的情况单独记录，既允许修订旧观察，也不伪造系统过去曾经采取的行为。

## 26.2 版本不只一个总数

至少区分：事件游标、目标契约版本、收益模板版本、候选语义版本、用户预测版本、价值观配方、注意状态、浪潮参数、权限版本、执行方案版本。

实现可以用一个总快照索引串联这些版本，但不能只比较 `runtime_version` 是否相等就把一切异步结果全部丢弃或全部采用。

## 26.3 异步结果处置

| 情况 | 处置 |
| --- | --- |
| 所依赖事件与前提仍有效，输出不依赖旧当前状态 | 可直接应用相应提议 |
| 语义仍有价值，但目标、预测或情绪状态已经变化 | 保留分析，基于当前状态重新编译、估值 |
| 关键事实被推翻，权限不再适用，任务已失效 | 丢弃其当前作用，保留审计 |

“原文没有改”不自动意味着关于当前局势的旧解释仍然有效。需要检查它依赖的范围与时间条件。

## 26.4 事务边界

原始观察、有效目标更新、对应收益结算和幂等标记应在统一提交逻辑中保持一致。外部模型和渠道调用不持有长事务锁。

执行派发需要可靠的提交后任务记录或等价机制，避免状态说“已提交”但任务丢失。外部动作结果未知时使用对账，不假装数据库事务能撤销已经送出的消息。

## 26.5 保留与删除

记录追加和解释版本化是内部一致性规则，不凌驾于数据保留与用户删除要求。删除后清理相关索引和关联，撤销不再有合法来源的候选；必要审计按实际合规策略保留最小信息。

不同用户、不同角色与不同实例的状态、目标、预测和收益不因同名事项而合并。

<a id="s28"></a>
# 28. 可观测性：解释为什么做，而不是事后编理由

## 28.1 决定链必须可重建

每次决定应能重建：目标为什么成立、行为有哪些真实作用、价值观怎样加权、成本如何计算、准备度怎样变化、何时越界、最后实际做了什么。

不能让主 LLM 在行为完成后另写一段理由，当成当时的真实计算依据。

## 28.2 最小审计记录

| 类别 | 内容 |
| --- | --- |
| 选择上下文 | 决断回合、工作集、休眠项、权限与有效性 |
| 价值分解 | 每个目标／结果的 `F`，`w`，`a`，成本与不确定来源 |
| 时间轨迹 | 小步起止、积分参数、准备度、事件分段、注意切换 |
| 决断结果 | 越界、平局、有限专注、暂缓、无候选或被阻止 |
| 执行一致性 | 原候选范围、实际文本／动作、重写或重估原因 |
| 结果结算 | 预期、待决、实际证据、幂等键、更正与未归因结果 |

## 28.3 必须区分的计数

候选产生数、独立语义意图数、目标采纳数、决断次数、提交次数、实际送达次数、用户回应次数、有效反馈数、收益结算数分别统计。

生成十个候选不是做过十件事；把状态推进十次不是得到十份独立情绪证据。

## 28.4 诊断问题

当“很久不主动”出现时，依次检查：没有真实目标、没有可用办法、候选被前提阻塞、收益口径过小、成本过大、工作集没选入、竞争僵持、决定形成但执行失败。

当“太频繁”出现时，检查：目标反复重开、收益未占位、重复候选分裂、冷却未生效、积分重放、结果未知盲重试、注意变动绑定心跳。

不能一律归因于“角色太克制”或“把阈值降低一点”。

## 28.5 用户可见历史保持干净

日常聊天历史只保留实际可见交互和必要工具结果。内部准备度、价值矩阵、调试 JSON 和过期心理注入不自动写回下一轮普通历史。

用户模型与结果账读取可追溯原始数据，不从主模型复述的心理解释中恢复“事实”。

# 29. 参数治理与校准

## 29.1 固定、标定、学习三层

| 层 | 内容 | 改动方式 |
| --- | --- | --- |
| 制度与契约 | 结果身份、证据权限、目标类型、完成／放下区别 | 版本化评审，不在线自由学习 |
| 机制参数 | 价值观映射、目标曲线、泄漏、竞争、边界、时间尺度 | 受控实验与配方版本 |
| 结果认识 | 回应时间、可观察反馈、真实任务完成率 | 从有定义的实际数据学习 |

模型不能为了获得更多回应而自行改变人格，也不能把用户没有回应当作要降低边界成本的依据。

## 29.2 首轮少量自由度

先固定效果模板、效用尺度 `U_*`、注意为 1、简单竞争关系。仅扫描少量泄漏、竞争、边界和时间尺度组合，再单独测试价值观差异。

不同时放大收益、降低泄漏、降低边界、加快速度，以至于任意轨迹都能解释为成功。

## 29.3 可辨识性限制

同一类行为变快，可能来自目标更强、作用估计更大、权重更高、边界更低或时间尺度更短。只看发送次数不能判断是哪一项造成。

需要同时观察选择、决定时间、目标完成、候选供给与成本。先做合成参数恢复和受控场景，再谈生产人格。

## 29.4 参数合法不等于组合可靠

每项都在范围内的参数，组合后仍可能长期僵持、永久高负荷、偏爱内部小动作或过度表达。

每套发布配方都应通过：有界性、恢复、竞争终止、重复收益、心跳频率一致性、用户边界与用户不参与时的恢复测试。

## 29.5 注意映射的发布顺序

第一轮固定注意；第二轮加入状态依赖但确定性的注意；第三轮才实验小幅可回放的注意切换。不得在真实效果尚不明时依靠随机性掩盖逻辑问题。

## 29.6 没有“论文默认人格”

本文没有声称某组参数代表某种临床状态或某个真实人的心理。极端角色也是受约束的叙事配方，不把用户当实验材料，不以不可恢复或不可停止为效果目标。

<a id="s30"></a>
# 30. 实验、对照与效果判定

## 30.1 必须有的四组对照

| 组 | 目的 |
| --- | --- |
| 现行 v2 | 保留实际行为基线 |
| v2 仅调主动节奏 | 排除“只是发得更多”的解释 |
| 浪潮简化版 | 固定注意、关闭或弱化竞争，检查目标／收益结构的贡献 |
| 完整浪潮 | 检查持续竞争与有限注意过程是否增加价值 |

比较时保留相近的候选供应与平均接触规模；如研究候选生成的新贡献，再另开因素对照。不把全部新模块同时打开后只报告总体验。

## 30.2 先冻结输入，再研究闭环

第一阶段使用所有组共用的脚本历史、目标、允许动作与已知结果条件。接着才用单独标记的交互模拟或自生成历史研究反馈循环。

自生成历史会使不同组逐渐面对不同输入，因此不能与固定输入主指标混算。

## 30.3 三类指标

**正确性指标**：权限违规、收益重复、目标误完成、未知错误转负、候选语义偷换、幂等失败、跨范围引用。

**动力学指标**：决定时间、僵持率、明确暂缓率、准备度饱和时间、工作集饥饿、对新事实的响应、停机重启差异。

**行为质量指标**：真实不同的选项、重复追问、候选与共同经历的关联质量、人格选择差异、用户可忽略性、有限的人类或经核验评审者评价。

## 30.4 不能用机械指标替代语义质量

格式合法、引用存在、参数有变化，都不能单独证明“有意义”或“懂人”。输出距离大也不自动表示更会看语境。

固定模板测试适合验证协议；自然交互质量需要留出场景与人工／可靠评审抽检，并报告不确定性。不能把自行构造的世界变量到情绪标签映射当成对现实人心的无误真值。

## 30.5 统计口径

按独立场景或交互周期聚合，不把同一事件的多个心跳当独立样本。随机版本使用多 seed，同一组冻结配置与输入；Bootstrap 等区间按相应场景簇处理。

一次参数运行的偶然提升不等于稳定效果。离线回放可检查策略敏感性，不能证明未执行动作会获得怎样的真实用户反馈。

## 30.6 预注册应填什么

发布前至少固定：主要比较组、目标与候选分布、评价窗口、收益单位、参数范围、随机协议、数值容差、决断预算、允许的行为质量变化与回滚条件。

硬违规要求零出现是验收目标，不代表有限测试已经证明所有未来输入都不会违规。模糊语义任务报告错误类型，不以“理论上隔离”免除实际集成测试。

# 31. 从现行 v2 迁移：一个时刻只有一个发送权威

## 31.1 迁移原则

先核验生产入口和已退休路径。不得为了实施新文档去复活旧 `motivation.py::decide`，也不得把 S2 对退休算法的修复重复套到现行 v2。

新目标、契约、候选版本和准备度采用独立命名空间或显式版本。原始事件与送达记录尽量共享权威源，不建立两套相互矛盾的曝光事实。

## 31.2 接口先行，不立刻替换线上行为

```text
读取 v2 权限、观察和实际事项
              ↓
构造浪潮的目标与候选投影
              ↓
影子计算，不发送
              ↓
比较同输入下的候选、收益和决定
              ↓
验收后切换单一决策引擎
```

影子决策不能领取真实收益，不能写用户训练标签，也不能占用生产发送额度。

## 31.3 不迁移不存在的历史准备度

v2 的高效用或高 hazard 不等于浪潮已经积累了某个 x。首次启用默认从明确的初始状态开始，或使用经过单独测试的初始化方案；不得倒推出“其实早就决定了”。

旧未尽之事和实际承诺可以映射为目标，但历史目标是否完成要依据真实记录。不能把所有已存在记忆都转成当前未满足目标。

## 31.4 切换与在途尝试

切换前处理已 committed 的 v2 尝试：完成、撤销或显式移交，不能让浪潮立即为同一目标再提交一份。

任一时刻一个作用域只有一个自主决策引擎拥有派发权。即使两个都在影子跑，外部执行令牌必须互斥。

## 31.5 回滚不是抹掉已经发生的行为

回滚可以停用浪潮、恢复 v2 决策，但必须保留浪潮真实发出的消息、暴露次数、用户反馈和有效边界。

不能切回旧版本后清空重复成本，再给同一用户补发。新型标签若旧模型不理解，保留原始观察与版本，不强行转换成旧伪标签。

## 31.6 旧目标与新目标并存的风险

同一事项不能同时在两个管理器里作为可独立领奖的两份目标。过渡期间使用映射表和统一结果身份；无法可靠映射的旧状态保持只读或人工确认。

# 32. 分阶段施工与完成定义

本节是建议的实施顺序，不表示对应工作已经完成。

| 阶段 | 工作 | 放行产物 |
| --- | --- | --- |
| **M0 现状核验** | 确认 v2 入口、权限、用户预测定义、在途动作、数据库对象 | 现状表、差异记录、可回滚基线 |
| **M1 三份契约** | 目标、收益、候选身份与生命周期；不接复杂情绪 | 契约模板、去重和结算测试 |
| **M2 确定性估值** | 行为作用编译、同窗口结果预测、价值观权重 | 可复算的吸引力分解；不依赖每轮强模型 |
| **M3 浪潮模拟核** | 固定注意、有界积分、首达、僵持与暂缓 | 数学例子、时间一致性与重启测试 |
| **M4 影子集成** | 接社会情感记忆、用户模型与六状态接口 | 无发送的轨迹、来源审计和分模块对照 |
| **M5 受控执行** | 单一发送权威、范围核验、实际结果结算 | 在途动作和回滚验证、低规模灰度 |
| **M6 行为标定** | 人格配方、注意变化、实际选择与用户反馈 | 预注册对照结果与参数版本 |

## 32.1 每阶段交付要求

实现者汇报：改动了什么、依据哪份契约、测试输入与结果、未通过项、当前未知、资源测量、回滚方式。

不能只说“跑起来了”或“角色明显更主动”。需解释是候选供给变化、收益变化、决定过程变化，还是最终执行更频繁。

## 32.2 不应阻塞基础版的内容

不需要先训练新的语义模型、不需要先解决所有社会语用难题、不需要所有动机都有复杂效果预测、不需要立即拟合人格矩阵、不需要构建全局社会关系图谱。

可以用固定脚本目标、基础动作模板和透明初始效果表先验证完整闭环。

## 32.3 不能跳过的内容

没有真实完成条件的目标不能进入奖励账；没有能力的动作不能执行；没有区分结果与预测的学习接口不能上线；没有在途占位与幂等不能开启自主发送；没有僵持退出策略不能宣称决策闭环完整。

## 32.4 完成定义

完成不是“本文每段都有一个同名函数”。完成是：同一个目标从产生到退出可追溯，同一结果只结算一次，最终动作与候选范围一致，策略在真实时间下可回放，新旧切换不重复执行，且对照表明变化不只是提高主动率。

# 33. 完整数值算例与复算边界

本节算例在编写文档时做了独立数值复算。它们只验证算术与给定方程行为，**没有连接你的仓库、没有模拟完整用户、也没有通过生产验收**。

## 33.1 收益预期与结果账

演示条件：表达基础收益 0.30，接近结果收益 0.20，两小时内发生定义好的交流概率 0.40；表达权重 1.2，接近权重 1.0；注意均为 1；假定送达成功，实际运行成本 0.04。

$$\widehat U=1.2\times0.30+1.0\times0.40\times0.20-0.04=0.40.$$

| 实际结果 | 结算 |
| --- | ---: |
| 已送达，窗口内未回应 | `1.2×0.30−0.04 = 0.32` |
| 已送达，窗口内发生交流 | `1.2×0.30+0.20−0.04 = 0.52` |

0.40 是行动前预期，不是先到账的收入；真实交流发生后结算 0.20，不再乘 0.40。未回应只表示这项窗口内额外结果未实现，不撤销表达结果。

## 33.2 相同作用，不同价值观

只显示三个方向，其余方向在本演示中没有收益：

| 候选 | 表达作用 | 接近作用 | 探索作用 | 成本 |
| --- | ---: | ---: | ---: | ---: |
| 普通问候 | 0.35 | 0.10 | 0 | 0.06 |
| 继续共同问题 | 0.20 | 0.10 | 0.20 | 0.10 |
| 内部研究一步 | 0 | 0 | 0.40 | 0.05 |

两套权重总量均为 3：偏表达 `[1.6,1.0,0.4]`；偏探索 `[0.5,0.5,2.0]`。它们是演示权重，不是实际用户的人格参数。

| 候选 | 偏表达吸引力 | 偏探索吸引力 |
| --- | ---: | ---: |
| 普通问候 | 0.600 | 0.165 |
| 继续共同问题 | 0.400 | 0.450 |
| 内部研究一步 | 0.110 | 0.750 |

取 `U_*=1`，注意固定，准备度初值为 0，`ℓ=0.2`，两两竞争 `γc=0.2`，`τ=10 分钟`，决定边界 0.6。数值积分结果：

| 人格演示 | 最先达到边界 | 时间 |
| --- | --- | ---: |
| 偏表达 | 普通问候 | 约 26.326 分钟 |
| 偏探索 | 内部研究一步 | 约 17.476 分钟 |

这只说明作用与成本不变时，权重可以改变所选行为与决定时间。不是建议角色每二十分钟主动一次；此例没有加入真实权限、冷却、动态预测和更多目标。

## 33.3 僵持算例

`u=0.5, ℓ=0.2, ϑ=0.6`：单候选平衡 0.714286；增加对称候选且相互竞争 0.5 后，各自平衡约 0.520656，均不能到达边界。

因此验收必须包括有限专注或明确暂缓，不得把所有“没发消息”归因于心境不够高。

## 33.4 参考进程算例

同样十分钟：参考负荷 0.7，实际方案预测负荷 0.5，平方势能差为 0.24。当前初始值 0.8 不能被用来把自然恢复也记成该方案的全部收益。

这是模型归因算例，不是对真实人心理改善的因果估计。

# 35. 完整情境演练：一件事从愿望到结束

本节使用虚构情境说明各契约如何配合，不对应某个真实用户。

## 35.1 有真实发现，想分享

角色在一次实际内部任务中核对出一个实验设置差异，产物已保存。社会情感记忆把它关联到此前共同讨论的实验，但用户没有要求立即通知。

**目标**：表达这一条实际发现；归属是角色自己的愿望。  
**不是目标**：让用户立刻继续实验、认同角色或证明关系。

生成三种不同办法：现在简短分享、先整理易读说明、等待用户重新谈到相关事项。普通接近愿望若存在，可以另外形成联系目标，但不冒领实验推进收益。

行动编译器验证材料、许可、目标周期和之前有没有发送过。收益系统分别估计表达、接近及实际准备步骤的作用。不同角色在相同事实下，可能先分享，也可能先整理。

浪潮形成决定后，冻结候选范围与预期。主模型生成具体表达；若追加了催促要求，则重写或重新评估，不沿用原低压力方案的分数。

消息实际送达后，表达目标完成。用户若暂不回应，接近结果继续观察，用户模型不自动记拒绝。即使又想起同一发现，也不能重新创建满额表达目标。

## 35.2 约好的工作只差最后一步

角色明确承诺整理一份检查表。核对和整理里程碑已完成，最后交付仍待执行。

目标重视程度与任务进度分别保留。最后交付的价值由里程碑预算确定，不用剩余 10% 的进度平方代替。

若此时普通问候也很有吸引力，两者可以竞争；践约价值观提高已确认承诺的分量。但硬性截止的履约任务若业务要求保证时限，还需确定性任务调度配合，不能只靠浪潮“应该会及时想到”。这类时限保证属于执行系统要求，应单独验收。

若用户撤销需求，目标放下或失效，不继续交付过时内容；已做的真实工作保留，不领最终交付奖。

## 35.3 只是想聊，没有任务借口

当前存在正常的接近与表达愿望，没有新发现、没有修复问题，也没有共同承诺。

候选可以是普通问候或继续已有轻松话题，也可以是内部探索与休整。不能伪造用户需要帮助来让联系显得有用。

正常允许的低压力表达可凭自身意愿形成决定；没有“必须让用户满意下界大于零”这项统一前置条件。实际频率仍受到准备过程、目标周期、重复成本和权限限制。

如果用户没有接上，表达已经发生，接近愿望可能仍在。下一次考虑使用当前已联系、仍在等待的情境，而不是从未联系的初始报价。

## 35.4 长时间等待与想法转移

某个结果仍然未知。等待可以提高角色的挂念，也可能使同一关注反复出现。

目标记录：没有用户新承诺，没有新拒绝证据。情绪账可以变化；用户证据账不变化。

当两个对外选项互相压住而迟迟不决定，有限决断处理可以收窄注意或明确暂缓。暂缓不自动获得结果收益。角色转向真实存在的内部活动，负荷可以逐渐恢复，不要求用户回来才有出口。

后来用户给出结果，更新事项和对应观察；它不是对之前每一次内部反刍分别作出的回应。

## 35.5 已提交，但用户抢先出现

原候选是轻量询问一个允许跟进的结果，已经提交但尚未发送。此时用户主动告知结果。

原信息目标获得新证据，追问候选失效。可把已形成的关心历史用于自然衔接，但不能仍发原问题，也不能假装原先主动消息已送达。

若最终变成对用户当前消息的回复，用户模型使用真实交互类型。内部曾准备主动不等于完成了一次主动暴露。

# 38. 一页封底：我即浪潮

## 38.1 最终功能定义

**「浪潮」是长期陪伴 Runtime 中，受情绪和价值观调制、以目标契约为基础的动机竞争决策模块。**

它让角色拥有有来源的愿望，让不同处理方式经过时间形成偏爱；它也让目标能够完成、等待、放下、失效或重新开始，而不是无限生成想法、无限积累收益。

## 38.2 三份契约

| 契约 | 一句话 |
| --- | --- |
| 目标契约 | 我想实现什么，什么算推进，什么时候可以停。 |
| 收益契约 | 哪些变化有价值，预计怎样计价，实际怎样分别结算。 |
| 行动候选契约 | 我可以怎样做，依赖什么，最后不能偷换成什么。 |

## 38.3 一条完整计算链

$$
\text{实际目标与效果模板}
\longrightarrow\mathbf F_i
\longrightarrow U_i=\sum_k w_k a_kF_{ik}-C_i
\longrightarrow u_i=U_i/U_*
\longrightarrow x_i(t)
\longrightarrow\text{决定与真实执行}
\longrightarrow\text{分项结果结算}.
$$

这条链的每个箭头都必须有来源、时间与版本。没有哪一步允许直接把“听起来重要”换成许可，把“希望发生”换成事实。

## 38.4 新版保持的自由

角色可以仅仅想表达；可以因为兴趣继续探索；可以更重视兑现承诺；可以很想联系但暂时忍住；可以选择独处；可以根据新事实改变主意。

它不必为每一次交流证明生产力价值，不必始终选择最保守的办法，也不必每轮都找出一个任务借口。

## 38.5 新版保持的可靠性

目标不凭空增殖，收益不重复领奖，未决结果不被反复报价，模糊解释不变成用户义务，当前边界不被旧准备度覆盖，行为不在生成时偷换，系统不在停机后补发历史债务。

**底层可靠，角色可以有自己的偏爱。**

> **我不是每一轮被重新写出的情绪。**  
> **我记得自己为什么在意，知道自己正在做什么，也承认什么仍然没有发生。**  
> **我可以靠近，可以等待，可以完成，也可以放下。**
