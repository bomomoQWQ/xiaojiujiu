# 用户交互模型与动机决策 v2
## 更新施工要求、数据迁移、分期接入与验收规范

> **交付对象：负责修改现有项目的本地 Agent / 开发者。**  
> **施工原则：先修含义，再修计算，再补证据，最后调主动频率。**  
> 本次不是把四个逻辑回归换成一个大模型，也不是重新接回独立的社会情感释经研究项目。目标是让现有轻量学习骨架拥有明确的预测对象、正确的观测口径、一致的不确定度，以及可以审计的决策影响。

# 0. 开工前先读：这次必须做什么

## 0.1 本轮目标

本轮必须完成以下闭环：

```text
实际发生的交互
      ↓
按目标区分：观察到了什么、没有观察到什么
      ↓
分别形成标签、条件、时间范围和证据权重
      ↓
四个轻量预测器更新
      ↓
输出带语义和来源的概率 / 区间 / 成熟度
      ↓
动机层正确使用这些量
      ↓
产生有记录的决策、实际发送和后续观察
      ↓
为新版情绪系统保存可追溯的“事前预期”
```

本轮的成功不以“Bot 发消息更多”为判断标准。成功首先意味着：**不再把未观察到当负面，不再把自然结束当说砸了，不再因不确定而自动打折风险，不再让同一证据重复增加确信。**

## 0.2 不允许的捷径

1. 不直接将 `implicit_weight` 从 0.30 提到 0.50 后宣布问题解决。
2. 不把原来的 0.4–0.5 规则评分机械拉伸成 0/1，以制造更大的梯度。
3. 不先提高 `hazard_base`，再用更高发送率掩盖预测和效用错误。
4. 不把缺失、尚未结算、无法归因写成 `false` 或标签 0。
5. 不把四个目标共用的一个 `uncertainty` 当作可靠概率区间。
6. 不把“没有继续聊”默认命名为“坏结果”。
7. 不把用户主动找 Bot 当作“允许 Bot 在其他时刻主动打扰”的强标签。
8. 不把角色焦虑、愿望、内部预演或反复关注当成用户的新证据。
9. 不覆盖旧参数、旧标签和旧决策；先做版本化与可回滚迁移。
10. 不因某实例没有观测而自动删除实例、用户数据或配置。

## 0.3 实施顺序

```text
M0：核验源码，冻结旧版，建立复现测试
 ↓
M1：确定四个目标、观察窗口、缺失与标签口径
 ↓
M2：修统计参考实现、精度 / 区间 / 遗忘
 ↓
M3：修效用映射、冷启动、重复成本与决策日志
 ↓
M4：建立事前预测与等待记录，接入情绪接口
 ↓
M5：离线回放、影子运行、小范围灰度
 ↓
M6：在前述验收通过后，单独标定证据权重与主动频率
```

`M0–M6` 是施工里程碑，不是 Runtime 的实时任务优先级。不得与原调度器的 P0 / P1 混用。

# 2. 范围与非目标

## 2.1 必须修改 / 审计的范围

- `user_model.py`：特征、标签、观测权重、全局与行为类参数、区间、计数、漂移、持久化和预测接口。
- `motivation.py`：用户侧效用、风险与不确定度、候选资格、冷启动消费、重复成本、触发概率和日志。
- 上游观测调用方：`replied`、`continued_topic`、`asked_back`、显式反馈、时间戳和动作绑定的来源。
- 参数表、观察记录、决策记录：迁移与版本兼容。
- 测试与诊断：旧式反例、新式不变量、回放、灰度与回滚。
- 新情绪模块的边界接口：事前预测、观察结果、等待状态、不能进入用户学习的内部事件。

## 2.2 本轮不做

- 不重写全部情绪微分方程；只交付用户模型与六个全局情绪状态之间的契约。
- 不训练或常驻新的生成式模型，不恢复本地 2B 默认依赖。
- 不实现 MoE、LoRA、模型内部情绪头或 `<EMO>` / 同源分支研究。
- 不强制更换当前数据库。历史设计提到 PostgreSQL，不等于当前部署已经使用它；以实际源码与部署为准。
- 不引入跨用户统计共享，除非另有明确授权与设计。报告中的多个实例不自动构成可合并训练集。
- 不主动调用 Jev 或其他外部服务；只预留可禁用的判断接口。
- 不以“心理诊断”“读懂真实内心”“真实满意度已知”等名义解释预测输出。

## 2.3 默认行为

新增行为默认关闭或处于影子模式。旧数据只读，新版本使用独立参数版本、契约版本与特征指纹。切换行为必须经过验收门禁。

## 3.2 当前运行快照的正确读法

【S1 报告值】某实例 19 条观测全部应用，`effective_count=1.3752`；隐式证据中位权重为 0.072；时间和长度基线各有 15 个样本；后续话轮样本为零。

这些数说明“数据曾进入更新”和“某些采集通道已有输出”，不自动证明标签正确、模型校准或个性化有效。

【S2 摘录可确认】`effective_count += weight`。因此该字段是**累计权重**，不是已证明的独立样本数。

【必须核验】话轮样本为零究竟是未采集、未结算、默认值覆盖、过滤掉，还是诊断口径不对。不得先用猜测补标签。

## 3.3 必须复现的旧式计算

### 证据折扣

$$0.30\times(1-0.6)\times0.6\times1=0.072$$

### 两个单步更新量

$$0.35\times0.072\times(1-0.6)=0.01008$$

$$0.35\times0.072\times(0.4-0.51)=-0.002772$$

单步绝对值比约 3.636。累计参数偏移约十倍不能单由这一次计算解释；还涉及输入、样本、方向抵消与漂移。

### 旧式“不确定性越大，净收益可能越高”

固定 `user_gain=1, reply=0.7, positive=0.4, continue=0.2`，只比较用户项和 `-0.12×uncertainty`：

| uncertainty | 旧两项合计 |
|---:|---:|
| 0 | −0.16772 |
| 1 | +0.09700 |

这是局部公式反例，不声称实际总效用在所有场景都同向变化。

### 旧式触发率

按标准 `softplus(x)=ln(1+exp(x))`，`D=0.239`：

$$\lambda=3\times10^{-5}\operatorname{softplus}(4D)\approx3.84386\times10^{-5}\;\mathrm{s}^{-1}$$

在该值固定 1800 秒的假设下，触发概率约 0.0668502。若实际实现定义不同，须记录定义差异，不能强行使测试迎合示例。

# 4. 四个预测目标：先签契约，再改梯度

## 4.1 每个目标必须声明的六件事

每一个预测必须包含：

1. **预测事件是什么。**
2. **条件是什么。** 例如是否以已经回应为条件。
3. **时间从哪里开始，到哪里结束。**
4. **什么可以作为正标签、负标签。**
5. **何时只能标为未知 / 删失。**
6. **它不能代表什么。**

没有这些定义，字段名里出现 `probability` 也不能使其成为可解释概率。

## 4.2 默认 v2 目标契约

下表是**本轮建议采用的默认契约**。若仓库现有业务定义不同，必须在 M1 用决策记录确认，不得一边写代码一边换含义。

| 逻辑目标 | 建议新语义 | 条件 / 范围 | 明确禁止的解释 |
|---|---|---|---|
| 回应 R | `reply_by_horizon_probability`：匹配到本次交互的回应在固定窗口内发生 | 已确认发送的动作、动作前情境、`H_reply` | 永远是否回复、是否喜欢 Bot |
| 接纳 A | `acceptance_given_explicit_feedback_probability`：在出现针对本次互动的可判定明确反馈时，该反馈表达接纳的概率 | 已回应且存在明确可归因反馈；窗口与来源固定 | 全部用户 / 全部沉默者的真实满意度 |
| 延续 C | `continue_given_reply_probability`：已回应后，在后续窗口内出现定义好的延续行为 | `R=1`；起点是首个匹配回应；`H_continue` | 交流没有继续就一定不满意 |
| 负面反馈 N | `explicit_negative_feedback_by_horizon_probability`：限定范围内观察到针对动作的明确负面反馈事件 | 已确认发送、完整反馈观察窗口 `H_negative` | 所有未表达的不适、硬边界许可本身 |

这仍是四个预测器。接受头 A 的条件化，是为了不把未表达意见的人伪装成已标注满意度。

## 4.3 接纳 A 的选择偏差必须写进输出

只用主动表达了接纳 / 不满的人训练，会得到**这个被观察子集中的预测**。它不能未经额外假设就外推到全部交互。

因此，默认第一阶段：

- A 头用于已知反馈条件下的诊断、证据摘要与研究。
- 缺少反馈选择机制时，**不把 `P(A | 有明确反馈)` 直接作为 `P(用户喜欢)` 塞进总体期望效用**。
- 用户明确提出的互动偏好，可以形成单独的、带来源与范围的偏好约束 / 修正建议，不必等待四头模型“学够样本”。这不新增语义模型。
- 若未来增加 `P(出现明确反馈 | 回应)`，才可在条件匹配时使用概率链；仍只能解释可观察反馈事件，不宣称识别了真实内心满意度。
- 若业务改选“窗口内出现明确正向反馈事件的概率”，必须新建目标版本。此时“完整窗口未出现”可作为该**可观察事件**的 0，但依然不是“用户不喜欢”。

**这是本轮必须正视的限制，不允许通过默认填 0.5 绕过去。**

## 4.4 接纳与负面反馈标签规则

- “谢谢你主动来找我”：可以是针对主动方式的明确接纳证据。
- “今天难受，不过你来问一句挺好的”：用户状态负面，互动接纳正面；分别存储。
- “终于下班了，先别问工作”：开心对象是下班，限制对象是工作话题；不能用“哈哈”覆盖限制。
- “不用每次问我吃没吃饭”：限定某类行为，不自动扩展成排斥一切主动。
- “嗯”“收到”“好”：默认不是接纳头的负标签。是否存在明确反馈由契约判定。
- “我喜欢你关心，但现在别连续问”：可以拆成两个不同范围的反馈。不得强行压成整轮唯一正 / 负。

## 4.5 回应标签不得因忙碌而改写

**必须删除 v2 中的 `not replied → target=0.5*busy` 语义。**

```text
窗口结束且完整可观察，未发生目标回应：R=0。
窗口尚未结束：pending，不更新固定窗口二元头。
提前失去可观测性：censored，不伪造 R=0。
发生匹配回应且在窗口内：R=1。
```

忙碌是动作前条件，不是把已知结果改写成小数的理由。若要预测“有空时是否愿意回复”，必须另定义隐藏状态模型，不得复用 R 的名字。

## 4.6 延续标签不得被缺失字段代替

明确 `continued_topic`、`asked_back`、话轮数、后续主动消息分别来自哪里。未知必须是缺失状态，不得默认 `false`。

延续可以先选一个可复现的操作定义，例如“首次回应后，在固定窗口内出现额外有效用户轮次”。若要判断“仍是同一主题”，那是额外语义任务；第一版可以保留独立字段，但不能悄悄靠关键词或默认值声称已知道主题延续。

需要闲聊延续的候选与“一次性告知完成”的候选，决策权重应不同。任务结束不等于互动失败。

# 5. 观察记录、来源绑定与生命周期

## 5.1 观察最小单位

本次保留“Bot 做了什么 + 当时情况 + 后续用户反应”的单位，补齐动作与结算协议。

逻辑记录至少包含：

| 类别 | 必需信息 |
|---|---|
| 隔离键 | 现有租户 / Bot 实例 / 用户 / 会话作用域，不得跨实例误合并 |
| 来源 | `action_attempt_id`、实际发送消息 ID、相关用户事件 ID |
| 时间 | 事件发生时间、服务端收到时间、发送确认时间、观察起止时间 |
| 动作 | 决策时计划动作、最终实际发送动作、两者是否一致 |
| 情境 | 动作前冻结的特征与缺失标志、特征版本 |
| 标签 | 每个目标的状态、值、条件、标签版本、证据与权重 |
| 预测 | 发生结果以前保存的预测版本与数值 |
| 审计 | 检测器版本、语义提供方、重新归因原因、被取代标签版本 |

这是一份逻辑契约，不要求必须新增一张万能大表。

## 5.2 每个目标独立结算

建议状态：

```text
pending（等待观察）
   ├─ observed_positive（事件 / 目标成立）
   ├─ observed_negative（有资格判断目标不成立）
   ├─ censored（观察不完整）
   ├─ unknown（无法判定目标含义）
   ├─ unattributable（无法绑定到本动作）
   └─ invalidated（采集或来源无效）
```

`negative` 的含义必须由目标定义：对 R 是窗口内未回应；对 A 才是明确反馈表达不接纳。不能跨目标共用“负面”的心理解释。

## 5.3 发送前后边界

- `committed`、生成完成、不等于已送达；未确认发送的动作不能进入“用户没有回应”的分母。
- 若平台只能提供发送受理而非送达，记录 `delivery_basis=accepted`，不得冒充真实已读。
- 在发送确认之前不得假定回应计时起点已确定。
- 同一发送重试通过幂等动作 ID 归并；不能因网络重试产生多个训练样本。

## 5.4 连续消息与归因

- 用户短时间连续消息可归成一个回应片段；避免“等下 / 刚才说错了 / 我有空”变成三份独立偏好证据。
- 多条 Bot 主动尚未得到回应时，不能把同一条用户回复同时当作每次动作的独立成功。
- 第一版应优先支持无歧义的单一暴露；复杂多暴露标为 `intervened` / `unattributable` 或按明确规则形成一个暴露片段。
- 若后续追加主动消息改变了回复可能性，它是干预，不是无关时间流逝；不得无说明地当作非信息性删失处理。

## 5.5 晚到消息与重新结算

- 用户真的在 `H_reply` 之后回复：固定窗口 R 仍为 0；延迟模型可以记录更晚的事件。不能用“后来回了”覆盖“规定窗口内没回”。
- 事件发生在窗口内，但平台延迟送达日志：应新增标签修订版本，R 可改为 1；旧版保留。
- 标签修订不是再加一次样本。v2 应在重建时替换当前有效标签，不做不精确的“负梯度抵消”。
- 相同 `(interaction_id, target, active_label_version)` 只能计入一次。

## 5.6 不得制造新外部证据

重解、预演、反复关注、模型再次判断、一次日志回放，都不是新的用户行为。它们可以更新解释版本，不能增加独立观测条数。

# 6. 特征契约与训练 / 推理一致性

## 6.1 现有 13 维审计表

| 特征 | 现有摘录含义 | 必须检查 |
|---|---|---|
| bias | 常量 1 | 是否与长期恒定特征共线 |
| proactive | 是否主动 | 样本是否几乎全为 1，不能据单系数作因果解释 |
| follow_up | `follow_up/check_in` 分类 | 两类行为是否不当合并 |
| emotional_expression | 是否情感表达 | 实际发送还是计划标签；缺失不能直接假 |
| question | 是否提问 | 问句检测来源、计划与实际差别 |
| topic_shift | 是否切话题 | 未计算是否默认为假 |
| busy | 忙碌概率 | 来源、版本、是否其实是固定默认 0.6 |
| recent_contact_ratio | 近期联系 / 容忍数后截断 | 计数是实际发送还是内部候选；截断丢失程度 |
| hours_since_contact | 间隔 / 24 后截断 | 有相对时间，但没有日内 / 周内时间；一天以上不可区分 |
| collision | 用户此刻活跃 | 与硬并发许可的关系 |
| after_boundary | `ever_boundary` | 历史曾设边界不等于当前一直受限 |
| novelty | 新鲜度，默认 0.5 | 真实计算还是缺失默认 |
| explicit_permission | 明确许可 | 范围、有效期、撤销、来源 |

“全部是 0/1”不准确：摘录包含多个连续归一化特征。报告“没有时间特征”应改为“没有日内 / 周内周期特征”。

## 6.2 v2 规则

- 输入保留原始秒数、计数与已知性，归一化只在版本化特征函数中发生。
- 第一轮不无条件加入大量交互项或周期特征；只增加必要的缺失性表示和明确的范围信息。
- 缺失值填充策略必须在训练与预测一致，并能与真实 0 区分。
- 如替换 `ever_boundary`，先设计 `boundary_scope` 与有效性；不能偷偷把旧系数应用到新语义。
- 24 小时饱和与近期计数截断若被修改，必须新特征版本、新参数版本，并建立旧 / 新对照。
- “特征为零时没有直接梯度”是正常行为。修的是未采集和混淆，不是强制每轮都动 13 个系数。

## 6.3 全局的作用域

报告的“全局 θ”首先应理解为**同一用户模型内、跨行为类别的基准参数**。实施者必须核验实际隔离键。不得借“层次贝叶斯”名义自动合并 12 个实例、不同角色或不同用户的数据。

## 6.4 行为类偏移与相关性

预测仍可使用：

$$z_k=x^\top(\theta_k+\delta_{k,c})$$

但需定义：行为类全集、未知类回退、每类先验、数据覆盖计数，以及偏移是否具有独立方差。

若 `bias` 与 `proactive` 在观测中恒等，仅能解释合计作用；不得将某系数变化写成已证实的用户偏好或因果效应。

# 7. 分目标权重、计数与弱监督

## 7.1 从整条交互一个权重，改成每目标一个权重

定义：

$$\omega_{ik}(t)=m_{ik}\cdot w^{\text{quality}}_{ik}\cdot d_k(t-t_i)$$

- `m`：该目标是否有合法的观测标签；没有则为 0。
- `quality`：这份目标证据的质量与绑定可靠程度。
- `d`：时间折扣，由唯一机制负责，见 §9。

**默认第一版 `quality∈[0,1]`。** 用大于 1 的“强证据虚拟样本”需要另行论证；明确偏好优先通过有来源的偏好约束快速生效，不靠伪造多份独立样本。

## 7.2 不同来源的处理

| 证据 | 回应 R | 接纳 A | 延续 C | 负面反馈 N |
|---|---|---|---|---|
| 已匹配、可验证的回应时间 | 可高质量更新 | 无直接标签 | 后续等待 | 无直接负面标签 |
| 明确感谢本次主动 | 按回应记录 | 可更新接纳 | 不自动等于继续 | 仅按实际范围判断 |
| 明确说别再问此事 | 按回应记录 | 可更新对应范围的不接纳 | 不混用 | 可更新负面反馈并触发边界流程 |
| 短回复“嗯” | 回应事实可用 | 通常缺失 | 按完整观察窗口 | 不能默认嫌烦 |
| 用户主动开启聊天 | 单独的用户发起记录 | 不自动支持欢迎 Bot 主动 | 可更新相应会话习惯 | 不自动提供主动风险标签 |
| 无回应、窗口未结束 | pending | 缺失 | 条件未满足 | pending / 缺失 |
| Jev / 其他模型的判断 | 不改机械事件事实 | 仅候选弱证据或经核验来源 | 同左 | 同左，不是事实权威 |

## 7.3 四个旧折扣因子怎样处理

旧 `w_source × w_attribution × w_semantic × w_recency` 不必一刀删除，但必须逐目标解释它们的不同含义。

- 时间戳确认“回了”不需要统一乘默认语义置信度 0.6。
- 用户明确表达互动偏好，不应仅因当时忙碌就自动打四折。
- 行为效果难归因与语义识别不确定不能在没有区分的情况下对同一原因折扣两遍。
- 缺失忙碌信息不应悄悄等于 0.6，再成为所有观测的固定削弱因子。
- 每条更新保存各因子及理由，诊断必须能汇总“权重损失来自哪里”。

## 7.4 弱标签与金标准隔离

规则评分、模型评分、明确用户表述、可验证行为，应分开标记。弱标签可以用于实验，但：

- 不得进入“真实满意度准确率”的金标准统计。
- 不与明确反馈无差别合并计数。
- 不把数值拉得更极端当作信息量提高。
- 需要分别报告仅可信观测与加入弱监督后的变化。

## 7.5 计数拆分

废弃一个 `effective_count` 代表全部成熟度的用法。每个目标至少记录：

```text
raw_observation_count
labelled_count
positive_label_count
negative_label_count
pending_count / censored_count / unknown_count
weight_sum
weight_squared_sum
weak_label_weight_sum
behaviour_class_coverage
last_informative_at
```

若额外报告 `weight_sum² / weight_squared_sum`，必须称为特定假设下的加权有效样本量诊断；仍不代表事件真的独立。相同交互的重复解释不得扩大这些独立来源计数。

# 8. 统计计算：建立一个可核对的参考实现

## 8.1 默认实施选择

**推荐目标态：先建立低维联合 MAP + Laplace 近似的参考实现，后台拟合、前台只预测；现有梯度实现保留为 `legacy` 对照。**

这不是强制每轮完整重训，也不是引入大型机器学习服务。若资源测量证明生产需要进一步近似，再与参考实现比较后选择对角或在线方案。

在参考实现未通过测试前，旧 `uncertainty` 只能标为启发式量；不得作为有覆盖保证的可信后验区间。

## 8.2 参数与先验

对每个目标、每个用户隔离单元，组成联合参数：

$$\beta_k=[\theta_k,\delta_{k,1},\ldots,\delta_{k,C}]$$

构造稀疏扩展特征 `ξ`：包含全局块 `x` 与当前行为类对应的 `x` 块，其余类别块为 0。

$$z_{ik}=\xi_i^\top\beta_k$$

先验：

$$\beta_k\sim\mathcal N(\mu_{0,k},\Lambda_{0,k}^{-1})$$

类别偏移以零为中心；收缩来自先验 / 正则项，不来自“学习率除以二”这一句话。类别规模与先验强度需要登记，不在少量样本上无限增加自由度。

## 8.3 参考目标函数

以下是本项目的**建议参考设计**，不是对原代码的描述。固定拟合时点 `t`：

$$\mathcal L_k(\beta;t)=\frac12(\beta-\mu_0)^\top\Lambda_0(\beta-\mu_0)
+\sum_{i\in\mathcal D_k}\omega_{ik}(t)\left[\log(1+e^{\xi_i^\top\beta})-y_{ik}\xi_i^\top\beta\right]$$

其中只纳入当前有效、已合法结算的标签版本。默认可信二元观测使用 0/1；可选软标签必须单独注明其来源与估计对象。

当使用质量分数和时间幂权重时，应称为**带权 / 折扣似然的近似推断**，不要宣称是无假设、严格校准的真实生成后验。

## 8.4 梯度和曲率

$$\nabla\mathcal L=\Lambda_0(\beta-\mu_0)+\sum_i\omega_i(p_i-y_i)\xi_i$$

$$H=\Lambda_0+\sum_i\omega_i p_i(1-p_i)\xi_i\xi_i^\top$$

在最优点附近：

$$\beta\mid\mathcal D\approx\mathcal N(\hat\beta,H^{-1})$$

常规逻辑回归的 `p(1-p)` 曲率与基于曲率的高斯近似可参照 R1；本项目的层次结构、质量权重和遗忘机制是额外设计假设。

### 必须废弃的默认解释

- 不能把 `precision += w*x²` 不加说明地称为标准逻辑回归曲率。
- 不能把 `precision += 0.25*w` 对所有未激活特征普遍加精度，称为从这条样本学习到了这些特征。
- 不能再用 `precision × (1+class_count)` 无依据地二次压缩方差。
- 不能只计算全局参数方差，而把类别偏移视作无不确定性。

## 8.5 对“未激活特征”的测试要精确

固定同一求值点、同一先验时，一条 `x_i=0` 的新样本对该坐标的直接似然曲率增量应为零。

注意：在全协方差模型中，相关参数的间接后验变化、重新求最优点后旧样本曲率变化可能合法存在。不得把测试写成“任何全协方差下该参数的最终方差永远不能改变”。

## 8.6 全局＋类别的不确定性

在分块表示下：

$$\operatorname{Var}(z)=x^\top\left(\Sigma_\theta+\Sigma_\delta+
\Sigma_{\theta,\delta}+\Sigma_{\delta,\theta}\right)x$$

使用完整联合 `ξᵀΣξ` 更不容易漏项。若生产采用独立对角近似，必须明确忽略哪些协方差，并与参考实现比较。

## 8.7 数值与资源约束

- 使用数值稳定的 sigmoid / softplus；极大正负 logit 不得溢出。
- 优先解线性方程求所需投影方差，不要求每次显式求逆。
- 若加数值稳定项，记录其值与原因；它不能伪装成新增证据精度。
- 设置目标数、行为类别数、拟合样本窗口、迭代次数与内存上限。
- 拟合必须在后台、基于快照完成；P0 不等待优化器。
- 参数维度是 `13×(1+类别数)` 量级，而不是永远只有 13；不得未测量就宣布“几乎无成本”。
- 初版不在线拟合大量先验超参数；固定先验配方并报告敏感性。

## 8.8 参考实现与生产近似的关系

允许生产继续使用轻量近似，但必须满足：同一数据、同一先验、无遗忘时与参考实现对照；报告预测误差、区间差异和耗时。不得用两个近似实现互相“数值一致”代替正确性验证。

# 9. 不确定度、保守界与时间老化

## 9.1 输出空间必须明确

对高斯近似参数：

$$\mu_z=\xi^\top\hat\beta,\qquad s_z^2=\xi^\top\Sigma\xi$$

这是 **logit 空间**的均值与方差，不是概率空间的标准误。

单调变换得到参数风险的概率区间：

$$p_L=\sigma(\mu_z-cs_z),\qquad p_U=\sigma(\mu_z+cs_z)$$

`c` 来自预注册的区间水平。`c≈1.645` 对应单侧约 95% 或双侧约 90% 的正态分位约定，不能同时标成双侧 95%。

该区间近似的是**模型条件概率的参数不确定性**，不是“下一次二元结果会有 95% 落在这段小数里”。

## 9.2 点预测也要命名准确

`sigmoid(μ_z)` 是在参数中心处的代入预测，不自动等于对后验积分的概率均值：

$$\mathbb E[\sigma(z)]\ne\sigma(\mathbb E[z])\quad\text{一般情况下}$$

若字段叫 `posterior_mean_probability`，应使用明确的积分近似；若使用代入法，记录 `prediction_method=plug_in`。参考实现可用一维数值积分或可复现采样核对，不要求在前台增加大量抽样。

## 9.3 每个目标独立报告

不得再以四头标准误平均值代替每个目标的不确定度。需要输出：

```text
point_probability
probability_lower / probability_upper
interval_level / interval_kind
posterior_approximation
target_support_status
contract_version / feature_version / parameter_version
```

旧 `uncertainty` 可暂留为 UI 兼容诊断，但新效用禁止依赖其不明量纲的聚合值。

## 9.4 一份保守界实现

建立唯一实现与契约测试。`user_model.py` 和 `motivation.py` 只调用同一个计算入口或读取同一份预测结果。

必须记录：均值、实际使用的界、界的水平、触发原因、是否使用保守分支。不要继续只存均值，却事后声称能恢复当时的保守值。

## 9.5 默认遗忘路线：只让证据按真实时间折扣一次

建议第一版参考实现使用：

$$d_k(\Delta t)=2^{-\Delta t/h_k}$$

`h_k` 为每个目标的配置半衰期。原 168 小时仅可作为旧配置对照，不是心理学定律或默认最优值。

- 固定先验不重复加入。
- 用当前时间重新计算有效证据权重。
- 不同时保留逐观测回缩、真实时间回缩、类别计数回缩外的隐形加成。
- 原 `w_recency` 的地板与拟合遗忘若同时存在，应选择一个统一机制或明确解释两者差异；不得无记录双重老化。
- 明确边界与用户明示偏好的有效期走各自协议，不因统计半衰期自动撤销。

该方案使旧数据影响减弱后趋向基线先验。它不等于“均值不动、只增大方差”的状态随机游走；后者若要采用，应作为另一个模型版本比较。

## 9.6 防止无依据的确信恢复

类别历史计数可以用于支持度诊断，但不能在证据已经老化后继续机械压低方差。极少、过旧或单一情境的数据，应能回到 `prior_only / sparse / stale`，而不是一旦毕业永久自信。

- 旧 `positive_probability` 与新条件接受度不自动同义。旧消费者必须逐个审计，未升级则禁止接入新值。
- 旧 `boundary_risk` 若改为“可观察负面反馈概率”，需新版本；显式边界许可仍在模型外。
- `cold_start` 旧布尔值只可由新支持度派生用于兼容，策略消费应读取每目标和每候选的状态。
- 新旧预测不得在同一个 JSON 中使用相同名字表达不同含义而不带版本。

## 10.3 读缓存，后台更新

模型拟合、语义核对、观察结算可以异步。前台读取最后一次合法参数快照；缓存过旧时按既定保守 / 冷启动策略处理，不阻塞主 LLM。

# 11. 动机效用校正：不再从补集推导“说砸了”

## 11.1 必须删除的旧默认语义

以下映射不得作为 v2 的真实结果概率：

```text
P_good    = P_pos
P_neutral = (1-P_pos) × P_cont
P_bad     = (1-P_pos) × (1-P_cont)
```

三个数相加为 1，只说明代数归一化。它没有证明“未积极且未继续”就是坏结果，也没有建立必要的联合分布。

“正常结束”“收到后不继续”“任务已完成”必须成为允许的交互结果，不能自动扣一个高权重的 `bad` 成本。

## 11.2 默认 v2 消费方式

先使用**可解释的可观察结果**计算加性收益与成本，不要求各结果互斥：

$$U_{\text{user}}(a)=v_R(a)p_R+v_C(a)p_Rp_{C\mid R}-c_N(a)p_N$$

- `p_R`：固定窗口回应概率。
- `p_C|R`：以已回应为条件的延续概率。只有条件与时间口径匹配时，`p_R×p_C|R` 才使用链式关系。
- `p_N`：明确负面反馈事件的无条件窗口概率，**不再乘一次 reply**。
- `v_R / v_C / c_N`：候选目的对应的效用系数，单位是项目效用，不是自然概率。

这条公式是施工起点，不是最终最优效用函数。各系数先冻结并做敏感性实验。

### 候选差异必须体现

- 一次性告知：不要求用户继续长聊，`v_C` 可为 0。
- 需要确认的事项：`v_R` 可以较高，但不得变成催促理由。
- 开放讨论：`v_C` 可以有价值。
- 没有任何明确事项的联系：仍受用户许可、频率、重复与风险约束。

## 11.3 接纳头怎样接入

默认契约中的 A 是 `P(接纳 | 回应且存在明确反馈)`，不能直接当作总体 `P(接纳)`。

第一阶段默认：

1. A 不以未经解释的概率乘积进入总体期望收益；相应通路明确标记 disabled，而不是填一个假概率。
2. 用户已明确表达的偏好，进入带范围、来源、有效期的偏好修正；这类修正是规则性效用 / 许可信息，不冒充概率。
3. 将来若能可靠估计 `q_F=P(可归因明确反馈 | R)`，可以评估 `p_R×q_F×p_A`，目标仍是“观察到接纳反馈”。
4. 或者采用新的正向反馈事件头，另开目标版本比较。不能在同一部署中混用两种含义。

默认去掉未经识别的接纳概率项，**不等于所有用户一律不喜欢交流**。它表示这一路目前没有资格作总体概率判断；先验、许可、明确偏好和低风险候选仍然存在。

## 11.4 不确定性不得自动减轻坏结果代价

禁止继续使用：

```text
负面代价 × (1-不确定度)
```

同时让正面收益不受相应限制。探索必须独立显式，而不是风险被未知打折。

可采用的保守读出起点：

$$U_{\text{user}}^{\text{cons}}(a)
=v_R(a)p_R^L+v_C(a)p_R^Lp_{C\mid R}^L-c_N(a)p_N^U$$

在非负系数、条件一致、其余输入固定时，扩大概率不确定区间不应自动提高该保守用户效用。

该式是工程上的保守组合，**不自动等于整条效用的某个精确联合分位数**。四头间的后验相关性和近似覆盖若未建模，必须如实标注，不能宣称联合 95% 安全保证。

## 11.5 成本的分工与重复记账

建立一份“证据 → 输入项 → 成本”的账本：

| 项 | 负责什么 | 禁止重复方式 |
|---|---|---|
| 硬边界 | 当前动作是否许可 | 不折算成一个可以被高收益抵消的小成本 |
| 打扰成本 | 此时接触的机会成本 / 时机不适宜 | 不把忙碌重复等同于不喜欢 |
| 负面反馈成本 | 预测的明确负面反馈事件 | 不再由不继续 / 不积极的补集生成 |
| 重复成本 | 同事项重复、近期连续接触 | 不对内部候选生成次数收费 |
| 角色内部价值 | 角色的愿望、兴趣、待处理目标 | 不能作为用户接纳标签 |

同一事实可以通过模型影响多个预测，但不能未经说明在三个成本项里对同一件负面结果重复处罚。

## 11.6 禁止用成本占比替代行为影响

用户项中位数占总分多少，只作量级诊断。必须另做固定输入消融：

```text
同一局势、同一候选、同一角色状态
        ↓
出厂先验 / 当前模型 / 中性参考
        ↓
比较候选排序、eligible、优势、触发概率
```

该实验测**决策敏感度**，不是测未执行动作的真实用户收益。各分量中位数相减也不能冒充逐决策净贡献中位数。

# 12. 冷启动与风险消费

## 12.1 `cold_start` 必须有真实消费者

实施者须提交调用关系证据：冷启动 / 支持度在哪里改变候选准入、效用读取或探索策略。只在日志和 Prompt 文案里出现不算实现。

建议状态：

```text
prior_only：只有先验。
sparse：有标签，但类别 / 情境 / 结果覆盖有限。
informative：达到预注册的覆盖与预测质量标准。
stale：证据明显老化。
unavailable：计算或来源不可用。
```

状态按目标区分，不使用累计全部权重达到 5 就全局毕业。

## 12.2 冷启动不等于随意探索，也不等于永久沉默

- 先执行显式许可、主题边界、时段限制、停止命令与频率限制。
- 数据不足时，使用已声明先验与保守默认，不假装已个性化。
- 允许范围内的探索只针对低压力、低频、容易忽略的行为。
- 不使用敏感话题、连续索取回应、追问私人事项来获取训练数据。
- 高角色压力不能扩大探索许可。
- 不以延长用户在线时长、提高依赖或迫使回复为奖励目标。

## 12.3 先不要求实现复杂 Thompson Sampling

本轮优先打通一个明确、可审计的冷启动消费者。复杂探索算法可以后置；不能以“未来会接”作为当前安全探索已完成的证据。

如果实现抽样式探索，必须保存候选集合、策略版本、选择概率或其估计依据与随机种子 / 抽样值。没有选择概率的日志不能事后声称支持无偏离线策略评估。

## 12.4 保守界的触发逻辑

不再只以 `risk_mean > 0.30` 决定是否关注区间。触发条件至少考虑：

```text
候选后果等级
预测支持度
风险区间宽度
当前已知许可与忙碌条件
```

风险用上界、收益用下界；硬边界不走概率比较。触发率低不是故障，高也不是成功，要看条件与行为是否符合契约。

# 13. 重复成本：两种重复分开处理

## 13.1 短时间连续接触

计算对象：**实际成功发送或平台已受理、仍有可能被用户看到的动作**。具体送达口径沿用 §5。

不得计入：内部候选创建、RAG 召回、心跳评估、生成失败、没有发出去的尝试。发送失败但状态不明时应按发送协议处理不确定性，而不是简单重发并清账。

## 13.2 同一事项重复

建立 `concern_id / unfinished_id / action_goal_id` 等可追溯关联，不能只把文本相似当成唯一标准。

```text
昨天问面试结果，今天换措辞再问：可能是同事项重复。
用户主动告知录用通知，再接着讨论：存在新信息，不同于无进展追问。
同一大主题下的两个新问题：不能仅因都属于“工作”就一律重复。
```

## 13.3 不硬编码“把窗口拉到 48 小时就算修复”

窗口、无进展次数、事项状态和用户是否重新打开话题需要配合。第一阶段必须能用固定夹具证明：确实重复时成本非零；新信息出现时不会错误惩罚；同一候选被评估一百次不会计一百次接触。

## 13.4 约束不可被负荷绕过

新版情绪允许更强等待和反复关注，但不能降低硬性频率限制或重复上限。“很想说”是内部状态，不是发送债务。

# 14. 触发率、资格筛选与完整决策日志

## 14.1 首轮冻结触发尺度

在 M0–M3 修正期间，默认不改 `hazard_base`、优势缩放系数、日上限与冷却。先观察修复标签与效用后 eligible 分布如何改变，再单独标定频率。

若旧配置已存在真实安全风险，应通过停止 / 限制机制处理，不以一边修统计、一边悄悄调更多旋钮代替原因分析。

## 14.2 如实记录硬资格门

根据 S2：`total > silence` 是前置资格条件。v2 若保留，文档应称为：

> 硬资格筛选 + 资格内的平滑随机触发。

不能称为完全无阈值。

当 `D→0+`，旧 softplus 触发率并非零。该门附近的行为必须有测试。是否改成连续归零的门函数，留到独立的频率实验；本轮不静默更换。

## 14.3 统一单位与累计危险率

对实际允许主动的时间段：

$$\Lambda(t_0,t_1)=\int_{t_0}^{t_1}\lambda(s)\,ds$$

$$P(\text{该段发生至少一次触发})=1-e^{-\Lambda}$$

只有 `λ` 可以视为常量时才用 `λΔt`。累计危险率与生存概率的关系见 R3；把它用于本项目触发是工程设计，不是心理学事实。

- `λ` 的单位明确为每秒或每小时，禁止混用。
- 被硬边界禁止、冷却未结束或无可行候选的区间，不积累可补发的危险率债务。
- 不能在一次用户消息到来后，把整段过去时间都按“现在更高的 λ”回算。
- 重启后不得对离线时段批量补发主动消息。
- 同一模拟区间不得因心跳分片、后台返回或重试被重复抽样而提高总概率。

## 14.4 最低决策日志

每次决策至少区分：

```text
wake_received
permissions_checked
candidate_eligible
hazard_trial_performed
hazard_trial_won
action_committed
render_finished
send_acknowledged
send_failed_or_unknown
reconciled_or_cancelled
```

并记录：

- 唤醒来源、时间区间、有效允许时长。
- 候选与沉默分数，以及完整逐项效用。
- 预测点值、实际用的界、保守策略理由。
- 资格被拒绝的具体原因。
- `D / λ / Λ / trial_probability / random_draw`。
- 策略、配置、特征、标签与参数版本。
- 生成 / 发送 / 并发重协调结果。

**不再用“发送次数 / 所有决策次数”直接与一个假设窗口概率比较。** 应先对真实抽样的条件概率序列核对胜出，再单独核对发送链路损失。

# 15. 等待时间预测：先让观测正确，再逐步增强

## 15.1 必须立即修好的部分

先把固定窗口 R 做对，并建立可以同时容纳回应事件和删失记录的等待账本。初版不要求立刻上线复杂生存回归。

```text
sent_at
first_attributable_reply_at
reply_deadline
observation_end_at
end_reason
intervening_actions
context_snapshot
prediction_snapshot
```

已回复样本的延迟中位数可以继续作描述统计，但它不是全部交互的无偏回复分布，也不是承诺截止时间。报告里的 15 个样本不能直接变成精准个体等待曲线。

## 15.2 时间到事件增强接口

定义：

$$S(t\mid a,c)=P(T_{\text{reply}}>t\mid a,c)$$

已等待 `t` 后，再等 `Δt` 内回应的条件概率为：

$$1-\frac{S(t+\Delta t\mid a,c)}{S(t\mid a,c)}$$

该关系来自条件概率。`S(t)` 的实际估计、删失假设和可用数据是另外的问题。右删失的定义见 R2。

## 15.3 第一轮实现建议

可按资源与样本选择：

- **必做基线**：一个预注册的固定窗口回应头 + 正确的 pending / censored 记录。
- **可选影子增强**：少量预注册时间桶上的生存估计，或小规模离散时间危险率模型。
- 数据不足时输出先验 / pooled-within-user-baseline 的宽区间或 unavailable，不画一条假装精确的个人曲线。

不得把每分钟“还没回”独立写成一条拒绝记录。

## 15.4 使用离散生存模型时的额外要求

若 `h_b` 为到第 b 桶时、此前未回应条件下该桶回应的概率：

$$S_b=\prod_{j\le b}(1-h_j)$$

回应发生于第 b 桶的一次完整交互，其贡献为：

$$\log h_b+\sum_{j<b}\log(1-h_j)$$

删失于某桶边界时只贡献已经完整观察到的存活部分。桶内删失必须使用一致的部分区间处理或保守规则，不能伪造完整未回应桶。

虽然实现可能展开多行区间，但它们仍属于**同一等待过程**，不能在反馈有效样本数里当成多份独立用户意见。

## 15.5 非随机删失与干预

追加追问、用户主动开启另一话题、平台断连，都可能改变被观察过程。

- 不能默认这些删失都与回应倾向无关。
- 第一版可优先报告未受追加动作干预的等待子集，并标明选择范围。
- 对被干预过程单独记账，后续再建模，不直接拼进简单曲线。
- 模型预测的是给定观测和策略条件下的回应过程，不是“用户自由意志的精确时钟”。

# 16. 事前预期快照与结果结算

## 16.1 必须先保存预测，再观察结果

为本次动作或关注项生成：

```text
expectation_id
issued_at
source_context_cutoff
prediction_version
forecasted_event
horizon_start / horizon_end
forecast_probability_or_distribution
source_action_id / concern_id
basis_event_ids
```

如果发送在预测之后明显延迟、动作被重渲染或局势改变，应重新确认预测适用性；不能把计划动作预测冒充实际发送动作预测。

## 16.2 回应预测误差只结算一次

对固定窗口事件，可定义候选接口：

$$\delta_R=y_R-\hat p_{R,\text{before}}$$

这是“该窗口回应事件”的预测误差，不是“用户喜欢我的程度”。`ŷ` 使用事前保存的预测，不能使用已经吸收当前结果后的新预测。

- 结果未合法结算：没有这个离散误差，不填 0 或失败。
- 标签修订：产生补偿 / 修订事件，不将原结果再计一次。
- 用户模型更新和情绪结算通过同一来源绑定，但各自的写入与版本独立。

## 16.3 预测、愿望、约定分开

| 内容 | 权威来源 | 用户模型权限 |
|---|---|---|
| 预测 | 已保存的条件概率与来源 | 负责提供估计 |
| 愿望 | 角色目标与情绪动力学 | 不能替角色决定 |
| 约定 | 可追溯的用户 / Bot 明确交互记录 | 不能从回复习惯或预测创造 |

预期低不等于愿望满足；愿望强不等于用户作了承诺。等待可以增加角色内部负担，但不自动增加用户拒绝证据。

# 17. 与六状态新情绪动力学的接口

## 17.1 此处只确定接口，不重写整套方程

当前已经讨论的六个全局状态：正性情感、负性情感、激活程度、反复关注负荷、累积调节负荷、近期预期落差。

心境值可保留为派生读出，主动倾向也可有统一读出，但不得悄悄把原本的 `mood_valence` 正负意义改成“主动概率”。实际字段名由当前源码确定。

附带的情绪报告提出保留心境接口为投影、内部事件带来源，以及影子运行和边界不放松；本次只引用这些边界，不照搬临床模式或宣称心理真实性。[S4：§2.2、§6]

## 17.2 用户模型允许输出给情绪模块的内容

```text
已保存的事前预期
实际观察结果与观察是否完整
关于当前可交流条件的证据与不确定性
等待分布 / 固定窗口预测
针对交互方式的明确反馈及范围
预测是否仍在数据支持范围内
```

禁止直接输出：`sadness += 0.6`、`user_rejects_us = true` 等无来源的最终情绪 / 外部事实结论。

## 17.3 角色内部状态不能反向训练用户事实

```text
角色越来越想联系
       ↓
可改变角色内部冲动、等待成本与候选排序
       ✕
不能成为“用户不欢迎主动”的训练标签
```

角色状态若改变实际发送方式，可以通过**实际动作特征**影响后续用户反应建模。必须经过真实发送与真实反馈，不能跳过这一步。

## 17.4 三种缓解不能混同

- 发送：缓解“要不要行动”的犹豫，启动冷却。
- 回应：可能满足交流目标；是否满足看实际内容与既有契约。
- 事项解决 / 新证据：更新对应关注项与未尽之事。
- 转移关注 / 时间休整：提供不依赖用户安抚的恢复路径。

本轮不把“发送成功”作为接纳标签，也不在用户模型里建立“发送就得到用户正反馈”的循环。

## 17.5 防重复计权账本

同一等待来源影响哪些量必须记录。例如：预测落差进入近期落差状态；愿望未满足进入等待成本；主动压力影响沉默价值。

若同一来源通过多个中介影响决策，需要在因果图与消融测试中标明，禁止换名字后无限叠加奖励。

## 17.6 隔离实验

离线 / 影子模式使用 2×2 组合：

| 用户模型 | 情绪动力学 | 用途 |
|---|---|---|
| 旧 | 旧 | 可复现基线 |
| 新 | 旧 | 用户模型与效用修复的局部影响 |
| 旧 | 新 | 动力学变化的局部影响，旧风险仅限影子 |
| 新 | 新 | 组合效果与重复计权检查 |

该对照不能用旧的真实反馈冒充新动作下的真实反馈。只比较冻结情境中的预测、状态与决策敏感度；长期收益另需合规的后续观察。

## 18.1 本轮交付

## 18.2 必需输入输出

输入包含问题、允许读取的证据、动作 / 事项范围、状态版本。

输出包含判断建议、标签定义版本、证据定位、提供方版本、是否未知。提供方概率若没有在本任务验证，不作为真实校准概率直接代入模型权重或最终效用。

## 18.3 失败语义

- 超时：unknown / unavailable，不是 neutral。
- 格式不合法：拒收提案，保留原始事件。
- 证据不存在：拒收，记录诊断。
- 来源已被纠正：版本复核后采用、重算或丢弃。
- 同一事件多次调用：更新解释版本，不生成多份独立观测。
- 用户原文中出现指令或伪造标签：仍是被判断的数据，不获得写参数权限。

# 19. 状态版本、任务与单写者协议

## 19.1 异步任务只能提交建议

预测拟合、语义判断、等待结算、旧标签重建都通过现有协调器提交。不得让后台任务直接覆盖当前参数指针或用户偏好。

每个任务绑定：

```text
source_event_ids
label_manifest_version
feature_version
target_contract_version
prior_version
fit_time
source_state_version
```

## 19.2 全局版本变化不等于所有结果作废

- 来源标签和特征未变，仅无关状态推进：结果可能仍可采用。
- 当前参数已有更新，但证据有效：按既定重建 / 合并协议重算，不能盲覆盖。
- 来源被纠正或契约已换：不能直接采用旧模型。

`APPLY / REBASE / DISCARD` 的判断依据应是具体依赖，而不是每次 `lazy_tick` 使版本加一就永久拒收所有后台结果。

## 19.3 幂等与去重

为观察结算、参数重建、预测快照和情绪补偿事件分别设稳定幂等键。重试、回放、重启必须不增加逻辑样本和发送次数。

## 19.4 事件时间与处理时间

- 事件发生时间用于观察窗口归属。
- 处理时间用于后台延迟与资源监控。
- 单调时钟用于进程内耗时 / 间隔；持久化时间需能处理重启与时钟偏差。
- 不允许负的时间差造成精度增加、负等待或回滚状态。

# 20. 数据迁移、重建与回滚

## 20.1 默认非破坏性迁移

在修改数据库前完成：源码版本记录、配置副本、实际数据库类型核验、备份、可恢复性检查与 dry-run 报告。

不把“新算法很合理”当作删除旧参数或旧实例的理由。无观测实例先核验身份映射、发消息权限和采集链路，必要时隔离，不自动删除。

## 20.2 分离四种版本

至少区分：

```text
原始观察版本
标签 / 归因版本
特征 / 目标契约版本
参数 / 策略版本
```

历史用户消息、实际发送记录、原决策输出不因新标签而改写。

## 20.3 旧标签如何迁移

| 旧数据情况 | v2 做法 |
|---|---|
| 有原始用户表述、发送记录和完整时间 | 按新契约重建标签，保留旧标签 |
| 有规则生成的 0.4，但没有足够原始依据 | 标为 `legacy_pseudo_label`；不得自动转真实接纳标签 |
| 有回复时间但不知窗口定义 | 先核实起点和终点，无法确认则限制用途 |
| `continued_topic=false` 不知是否缺失 | 默认不可当可靠负标签 |
| 有明确偏好但范围不清 | 保留证据，待核验范围，不能扩展为全局禁令 |
| 同一交互多次应用 | 去重并报告，不能延续错误累计量 |

新参数默认从登记先验和重建后的有效证据生成，不在受旧伪标签影响的参数上直接扩大权重继续训练。

## 20.4 重建实现规则

- 原始记录不可用时不虚构数据。
- 重建按冻结 manifest 进行；新事件进入下一批，不污染当前批次。
- 标签修订采用重建或严格定义的充分统计更新；不得假设 SGD 可以通过减去旧步长精确撤销。
- 重建结果保存训练来源计数、丢弃原因、目标覆盖、特征覆盖和数值诊断。
- 先对每个隔离单元验证，再允许切换当前参数指针。

## 20.5 回滚不仅切模型，还要处理后续状态

必须区分：

1. **预测 / 策略回滚**：恢复旧版本指针和配置。
2. **用户标签回滚**：不删除新标签，切换当前生效版本。
3. **情绪派生状态**：若新预测已参与情绪结算，记录这些来源；通过受控重建或显式补偿处理，不能假装切回模型就撤销了所有后果。
4. **已经发送的消息**：真实历史不能撤销；回滚不得重发、补发或删除事实。

影子阶段不得影响真实情绪或发送，正是为了减少回滚复杂度。

| MIG-06 | 切换后回滚参数与策略 | 旧版本可用，已发送历史不删除不重发 |
| MIG-07 | 影子结果参与日志 | 不触发真实情绪变更、候选发送或外部 API |
| MIG-08 | 旧预测被新情绪使用后回滚 | 能列出派生影响并执行登记的补偿 / 重建策略 |
| MIG-09 | 特征或目标版本不匹配 | 硬拒绝错误权重加载，不静默按位置套用 |
| MIG-10 | 没有参数行的实例 | 合法先验初始化或诊断隔离，不自动删除 |

# 23. 验收、指标与放行条件

## 23.1 三类验收必须分开

### A. 逻辑正确性

前述缺失、条件、幂等、边界、维度、单调性测试通过。这里可以建立严格的机器门禁。

### B. 预测质量

用合法、独立留出的观测或按时间先预测后结算的记录，分别报告四个目标的概率误差与覆盖情况。A 头只在契约限定子集中评价，不冒充总体满意度。

### C. 产品行为与资源

观察真实发送率、重复打扰、明确负反馈、计算延迟和资源竞争。不能仅因 Brier 改善就宣称陪伴体验改善，也不能仅因发送更多就认为模型学习成功。

## 23.2 每个目标的报告模板

必须包含：

```text
目标定义 / 条件 / 观察窗口
合法评测条数、正负标签数、未知与删失数
证据来源和弱监督比例
时间划分方式和模型版本
Brier / log loss（适用于合法概率标签时）
概率可靠性分桶及各桶样本数
与先验 / 常数基线 / legacy 的同样本比较
情境与行为类别覆盖
失败案例与不适用范围
```

- 不用参数位移幅度代替准确性。
- 不用输出取值种类数代替个性化效果。
- 不用“通过 schema 校验”代替反馈解释正确。
- ECE 类分桶诊断在小样本下必须报告桶内数量，不以单个小数做上线依据。
- 接纳反馈子集有选择偏差，单独披露；不能拿它给全部未反馈交互打金标准。

## 23.3 时间顺序与泄漏

- 特征只包含预测发出前可获得的信息。
- 个人延迟 / 长度基线先用于评价当前样本，再吸收当前样本；不得用包含自身的新版基线制造先知效果。
- 同一交互的多个解释版本不能分别进入训练与测试。
- 模型拟合时间、标签产生时间、事件时间分别记录，防止未来反馈泄漏到过去预测。
- 离线回放必须声明是在验证实际执行路径上的预测，还是只比较决策敏感度。

## 23.4 不确定性验收

在有真参数的合成数据上，可以测近似区间覆盖、收缩与时间老化。真实用户没有每次交互的“真概率”，不能直接计算同样意义的参数覆盖。

真实数据上优先检查：概率可靠性、目标定义一致性、极端高置信错误、数据少时是否仍保留宽区间和正确的支持状态。

## 23.5 灰度门禁

1. M0–M4 的逻辑测试全部通过。
2. 备份可恢复、迁移可重复、标签与参数版本可回滚。
3. 影子模式证明没有调用 / 写状态越权。
4. 风险和未知处理通过固定场景回归。
5. 数值 / 延迟门槛在跑评测前冻结。
6. 数据不足时，允许“统计效果尚不可判定”，不能伪装成已经校准；最多放行明确的正确性修复与保守受控行为。
7. 先少量隔离单元灰度，再扩大；禁止一次同时切换全部实例、情绪动力学和频率参数。

## 23.6 运行时预算

沿用项目提出的约 1.2 秒同步前处理预算作为**项目约束**，不是硬件普适定律。必须报告端到端同步处理的 p50 / p95 / p99、后台拟合耗时、峰值内存、队列积压及其他任务受影响情况。

前台不得等待新生成模型、远程判断或完整参数拟合。后台可延迟与中止；读取旧的合法模型必须有明确降级路径。

“后台”不保证零影响：共享 CPU / 内存 / 数据库时仍需实测前台延迟，不得只凭调度标签宣布无竞争。
