# 「浪潮」决策引擎 M0 机械历史迁移规范 v1

## 1. 目标与边界

把停服一致性快照中的每用户 SQLite 机械层事实导入对应 PostgreSQL per-user schema。迁移不重算事实、不生成新解释、不恢复旧在途发送，也不把已退休 v1 用户模型参数带回生产。

### 默认迁移

1. `raw_events`
2. `event_semantics`
3. `interpretation_versions`
4. `memories`
5. `memory_candidates`
6. `unfinished_matters`
7. `boundaries`

### 默认重建，不迁移

- `activated_memories`：当前激活工作集，停机后易陈旧，由长期记忆和新上下文重建。
- `working_situation_items`：短期局势投影，跨停机恢复会把旧情境误当成现在。

只有显式 `include_rebuildable=true`、通过引用与时效验证时才允许纳入以上两表。

### 不属于本迁移

- action attempts、outbox、旧决策、用户模型参数；旧在途行为不得重放。
- v1 用户模型 evidence migration；该迁移已有独立 planner/audit。
- 目标/收益/候选三契约；这些由「浪潮」新命名空间创建，不从历史评分倒造。

## 2. 作用域与身份

- 一个用户对应一个 PostgreSQL schema；隔离边界是 schema，不给 core 表补 `scope_key`。
- SQLite 主键全部原样保留为 PostgreSQL `TEXT`，不得重写成 UUID。
- `raw_events.seq` 不是唯一键，不得用作幂等键。
- schema 名必须符合 `[A-Za-z_][A-Za-z0-9_]*`。

## 3. 来源快照要求

- SQLite 必须来自停止写入后的完整快照，或 SQLite backup API / `VACUUM INTO` 产物。
- 若直接复制主文件，必须证明 WAL 已 checkpoint 且 sidecar 一致；否则拒绝。
- 使用 `mode=ro&immutable=1` 打开。
- 导入前执行 `PRAGMA integrity_check`，记录文件 SHA-256、大小、mtime、schema version、table_info 和每表计数。
- planner 与 dry-run 不得写 SQLite 或 PostgreSQL。

## 4. 类型转换

| SQLite | PostgreSQL | 规则 |
|---|---|---|
| ID/Text | `TEXT` | 必填 ID 非空，正文不 trim、不改写 |
| `INTEGER` | `BIGINT` | 拒绝 bool 冒充整数及超出 BIGINT |
| `REAL` | `DOUBLE PRECISION` | 拒绝 NaN、+Inf、-Inf；不自动 clamp |
| 时间 `TEXT` | `TIMESTAMPTZ` | 必须可解析并具时区；统一 UTC，不用当前时间填补 |
| JSON `TEXT` | `JSONB` | 严格解析并校验顶层 object/array，不用宽容 loader 静默默认 |
| SQLite bool | `BOOLEAN` | 仅接受 0/1；其他值拒绝 |

数组 JSON 保持元素顺序。canonical JSON 只用于 hash、幂等比较和审计，不改变数据语义。

## 5. 逐表规则

### `raw_events`

- PK：`event_id`。
- `metadata_json` 必须是 object；`source_event_ids` 必须是 array。
- `timestamp`、`created_at` 转 UTC aware datetime。
- 全量迁移，作为 append-only 事实底座。

### `event_semantics`

- PK：`event_id`。
- 必须能引用迁移后的 `raw_events.event_id`；孤儿拒绝或隔离。
- 保留当时解释，不在迁移时用新模型重算历史。

### `interpretation_versions`

- PK：`interpretation_id`。
- 审计自然键 `(target_kind,target_id,interpretation_version)` 重复。
- 审计 `supersedes_id` 自引用、缺失与环；不静默修复。
- `source_event_ids` 必须是 array。

### `memories`

- PK：`memory_id`。
- `structured_json` 必须是 object；`topics_json`、`source_event_ids` 必须是 array。
- 审计 status/archived_at 一致性及来源覆盖率；历史裁剪造成的缺失只报告，不伪造来源。

### `memory_candidates`

- PK：`candidate_id`。
- 迁移 pending 候选及 consolidation 谱系。
- `consolidated_memory_id` 非空时必须引用迁移后 memory。
- 若旧 schema 缺后加列 `structured_json`，可按其原 schema default `{}` 合成，但必须在 plan 中记录 synthesized column。

### `unfinished_matters`

- PK：`unfinished_id`。
- 已解决/过期行仍迁移，保留历史并防止重启错误复活。
- 迁移时不依据当前时间删除；仅审计 active/stale/status 分布。

### `boundaries`

- PK：`boundary_id`。
- 安全优先：任何转换、冲突或引用异常都阻止该用户上线。
- 已撤销和已过期边界仍全量保留。
- SQLite bool 仅接受 0/1。
- 旧 schema 缺 `subject` 时可合成 `NULL`，必须记录。
- 导入后逐项核对 active boundary 和最严格行为，绝不以较宽松目标值覆盖来源。

### 可选 `activated_memories`

- 必须在 memories 后导入且每个 memory_id 存在。
- 拒绝负 recall_count 和非有限 activation。
- 任何 cutoff 都必须成为显式 plan 参数和审计字段。

### 可选 `working_situation_items`

- 最后导入。
- 只允许仍有效且引用可解析的行；过滤条件进入稳定 plan hash。
- 默认禁用。

## 6. 幂等与冲突

每表使用原 PK 作为 row identity。禁止裸 `ON CONFLICT DO NOTHING`：

1. 目标无同 PK：计划为 insert。
2. 同 PK 且所有规范化列完全相同：exact duplicate。
3. 同 PK 但任意规范化列不同：hard conflict，输出列级差异，整用户事务回滚。

不得对 append-only 历史执行 UPDATE；对安全边界也不得静默覆盖。导入 run identity：

```text
(target_schema, source_snapshot_sha256, plan_sha256, importer_version)
```

row hash：

```text
(table_name, primary_key, canonical_transformed_row)
```

## 7. 事务与导入顺序

每用户一个 PostgreSQL 事务，并持有目标 schema advisory lock：

```text
raw_events
→ event_semantics
→ interpretation_versions
→ memories
→ memory_candidates
→ unfinished_matters
→ boundaries
→ [activated_memories]
→ [working_situation_items]
```

目标 schema 必须先通过 checksum migrations；未知未来版本或 checksum 不匹配立即停止。使用 schema-qualified SQL 或事务内 `SET LOCAL search_path`。

## 8. 审计与 quarantine

机械导入使用独立 append-only ledger，不复用 user-model migration audit。

每次 plan 至少记录：

- source hash/path/size/mtime/schema version；
- target schema、代码提交、importer version；
- timezone/default/cutoff/optional projection 策略；
- 每表 source/convertible/insert/duplicate/conflict/quarantine/filtered 数；
- 每表 source canonical hash 和 transformed hash；
- 关系完整性审计与状态分布；
- plan SHA-256。

quarantine 只存表、PK、原因和 payload hash；正文等敏感内容不重复复制。

## 9. 验收

- `inserted + exact_duplicate = accepted_source`。
- 迁移选定 PK 集合差异为空。
- source transformed hash 与目标同 PK canonical hash 一致。
- active boundaries 逐项一致。
- 第二次 dry-run：`would_insert=0`、`exact_duplicate=accepted`、`conflict=0`。
- 默认不迁的两张工作投影表保持为空或仅含切换后明确保留的数据。
- 导入后做 schema dump；生产恢复前完成恢复验证。
