## 4. 上线中发现并当场修掉的三个真实缺陷

1. **环境变量类型强制转换错误**（`23e69c6`）
   `CR_LANGCHAO__ATTENTION_RECIPE=off` 被标量猜测器转成布尔 `False`，11 个 Runtime 全部启动失败重启循环。
   现在按字段声明类型解析：字符串字段永不改型，布尔/整数/浮点严格校验，列表字段必须显式 JSON 数组。

2. **列表配置无法通过环境变量下发**（`8eb0955`）
   `live_scope_allowlist` 之前会被写成裸字符串，而它是精确 scope 门禁 —— 字符串会退化成子串匹配。
   现在要求 JSON 数组，否则 fail-closed。

3. **v18 派发 witness 冻结了历史行**（`e90a25e` / `eff5113` / `4a3b936`）
   `action_attempts` / `outbox` 的 BEFORE INSERT 触发器在 `INSERT ... ON CONFLICT DO UPDATE` 时也会触发，
   而全部历史行都没有 `dispatch_claim_id`，导致每次 v1 事件上报都抛
   `ConflictError: action attempt ... has no live dispatch claim`。
   v25 保留真正的不变量（**没有 claim 就绝不允许进入可派发状态**），但允许历史行继续记账：
   - 新行仍然必须有 claim；
   - 无 claim 行不得变成 `committed/rendering/ready_to_send`（attempt）或 `pending/leased`（outbox）；
   - 无 claim 行永远拿不到 witness 字段。

4. **插件缺 completion metadata**（插件仓库 `9baa69b`）
   严格模式下渲染结果必须带 `render_metadata`，否则 Runtime 拒收。插件已补上并重启 AstrBot。

5. **feature version 升级后历史行读不出来**（`c39be6d` / `7540586`）
   把特征定义升到 `user-model-v2.1-render-plan-v1` 后，读取旧标签/旧特征快照会抛
   `ValueError: feature_version must be ...` / `stored feature snapshot has an unsupported feature version`，
   表现为**调度轮直接失败**（「浪潮」连决策都跑不完）。
   修法是分清「读历史」和「学历史」：
   - 读取：接受全部已知版本（`USER_MODEL_V2_FEATURE_VERSIONS`），旧特征快照按原样携带（`StoredFeatureSnapshotV2`），
     重写时逐字节保持，**绝不**用新编码器把它"升级"成看起来像当前版本的数据；
   - 学习：`build_fit_dataset` 本来就用 `feature_version` + `feature_fingerprint` 过滤，旧行自然被排除。

## 5. 回滚手册

### 5.1 只回退发送权威（最快，秒级，推荐先试）

```bash
# 在 fleet 容器里对目标 scope 执行：
docker exec -i xxj-runtime-fleet python - <<'PY'
import os, psycopg
from companion_runtime.langchao_authority import AuthorityEngine, AuthorityMode
from companion_runtime.langchao_authority_repository import LangchaoAuthorityRepository
scope = "default:FriendMessage:<QQ>"
conn = psycopg.connect(os.environ["CR_STORAGE__DSN"], autocommit=True, row_factory=psycopg.rows.dict_row)
conn.execute('SET search_path TO "cr_' + scope.replace(":", "_").lower() + '", public')
repo = LangchaoAuthorityRepository(conn, scope_key=scope)
repo.switch_authority(engine_key=AuthorityEngine.RUNTIME_V2, mode=AuthorityMode.LIVE,
                      expected_pointer_version=int(repo.get_active()["pointer_version"]),
                      in_flight_count=0, reason="rollback to runtime_v2")
print(repo.get_active())
PY
```

切换后 Runtime 在下一轮就会改由 v2 发送，无需重启。

## 7. 已知限制（上线即生效，但不是缺陷）

- **hazard 很低**：`hazard=2.4e-05`，`action_probability=3.3e-05`，所以「浪潮」绝大多数轮次选择沉默。
  这是设计意图（低打扰），不是故障；主动消息本来就该稀疏。
- **注意力配方为 off**：全 1 权重、无竞争。B2/B3 已实现但未授权，需要单独决定是否启用。
- **隐私删除路由未挂载**：模块已就绪，等明确授权再加 token 并开启。
- **最终措辞不作为预测特征**：实际文本只做审计 provenance（render-plan 结构特征才进模型），
  因此现在学的是「计划类型 + 上下文 → 用户反应」，不是「具体句子 → 用户反应」。
- **未验证真实平台 canary**：隔离 loopback canary 通过，真实 NapCat 链路靠本次上线观察。
