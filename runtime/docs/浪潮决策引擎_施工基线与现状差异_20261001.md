## 已确认的现状差异

### 可复用

- PostgreSQL per-user schema、checksum migration、scope 隔离。
- 用户模型 v2 的固定窗口标签、缺失/删失、MAP/Laplace、参数 CAS。
- hard boundary、repeat_v2、authorize、attempt/outbox/send-ack。
- 记忆的来源、结构化+摘要、冲突谱系、检索激活。
- append-only 审计思想与公共只读 evidence。

### 必须替换

- `runtime_v2.py` 的 `eligible → argmax → hazard → draw`。
- `D=max(real advantage, cold-start exploration advantage)`。
- `motivation_v2.py` 作为最终总效用的角色；它只保留为用户后果预测适配器和 v2 回滚基线。
- 强制 hazard 阶段的现有决策审计契约。
- 自由文本 `goal` 充当事项/目标身份的做法。

### 必须新增

- 目标契约、目标周期与谱系。
- 收益契约、结果令牌、预期账与实际结果账。
- 行动候选契约、稳定语义身份、修订与 envelope。
- 「浪潮」准备度状态、同步积分步骤、首达、僵持、暂缓与持久恢复。
- committed snapshot、pending result placeholder、engine authority。
- 社会情感记忆投影和删除来源后的依赖失效。

4. 多个 fleet 语义配置环境变量使用旧单下划线命名并被日志报告为 ignored，需要整理配置权威源。

## 分阶段完成定义

### M0 现状冻结与事实底座

- 冻结 v2 行为/决策/发送/标签/恢复回放。
- 机械历史迁移：memories、必要 raw events、unfinished matters、边界与确认安排。
- expectation 生产插入链路。
- 在途 attempt、迟到 ack、未知送达恢复测试。

### M1 三份契约

- Goal / Reward / Action Candidate 的 frozen DTO、版本、稳定 key、状态机与校验。
- 不接发送，不让强模型写最终收益、权限或准备度。

### M2 Schema 与 Repository

- 只追加 v9+ migration。
- immutable revision + active pointer + placeholder + outcome ledger + engine authority。

### M3 确定性估值

- 固定模板、`a=1`、固定 `U*` 与价值配方。
- 送达、交流、里程碑、过程价值分账。

### M4 「浪潮」数值核与影子集成

- 纯函数有界积分、同步更新、首达、平局、僵持、明确暂缓、步长收敛、停机恢复。
- 真实 v2 输入上只写轨迹，不发送、不领奖、不训练用户事实、不占发送额度。

### M5–M7 受控执行、社会情感记忆、标定与上线

- 单一发送权威。
- 最终文本 envelope 核验、并发重协调、真实结果分项结算。
- 先模拟号，再当前用户 scope，再低规模灰度，最后恢复真实 NapCat。

## 不可破坏不变量

1. 硬边界、删除、停用和权限永远在竞争场外。
2. 同一事实只结算一次；预期不等于实际收益。
3. 目标、候选、行动尝试、结果令牌身份分离。
4. 停机不补发历史动作；降低阈值不倒造历史决定。
5. 一个 scope 同一时刻仅一个引擎拥有自主发送权。
6. 影子「浪潮」不发送、不领奖、不训练、不占额度。
7. 外部模型只提议，不写最终 U、x、权限、完成或用户后验。
8. 所有时间推进使用真实时间差并可回放；积分顺序不依赖数据库或哈希遍历顺序。
